## 0. 結論

前回「V2修正版は通過」とした判定は撤回する。公平感、作業上限、配信SLAは通ったが、BAAOの現金採算が通っていなかった。

- 3案件合計のBAAO即時キャッシュ: P10で約▲16.9万円。
- Commissioned Case: 案件別P10で約▲30.9万円。
- Enterprise Knowledge: 案件別P10で約▲51.5万円。
- Partner Knowledge: 案件別P10で約▲40.3万円。

将来のCase資産価値やKnowledge販売期待価値を足して受注可否を判断したことが原因である。これは「価値がある」と「儲かる」を混同しており、制度の通常取引としては不適切だった。

修正後は、BAAOの採択条件を次へ変更した。

1. 将来資産価値を取引採算に含めない。
2. 入金済み売上から著者報酬、ロイヤリティ、直接工数、見積・審査工数を引く。
3. 成立した全取引で、P10粗利が0円以上かつP10粗利率20%以上とする。
4. Sponsored CaseとKnowledgeは、顧客またはスポンサーから100%前受けできた場合だけ制作を開始する。
5. 案件間の黒字・赤字を相殺しない。
6. 見積・権利確認の開始前に、原価へ20%の粗利を乗せた返金不可のスコーピング料を受け取り、成約時は本体価格へ充当する。

キャッシュ採算ガード案は、心理・運営・採算の8条件をすべて通過した。

| 指標 | キャッシュ採算ガード案 |
|---|---:|
| 公開Case期待値 | 1.40 / 3件 |
| Knowledge期待値 | 0.27 / 最大2件 |
| 公平感代理値 | 中央値5.6 / 7 |
| 標準Case作業 | 中央値8.0h |
| 配信SLA | 95.0% |
| 3案件合計の実現粗利 | P10約68.7万円 / 中央値約77.3万円 |
| 成立取引の最低P10粗利率 | 20.0% |
| 不成立を含む提示導線の最低P10粗利 | 3,000円 |

したがって、現行CBAAの12% / 5%は新規適用を停止し、Lead、Delivery、Case、Knowledgeを別取引に分ける。ただし、料金は恒久確定ではない。実運用で見積・失注・制作・配信工数を計測し、全件黒字の条件を維持したまま更新する。

## 2. 模擬パイロットの設計

### 2-1. 3案件類型

| 類型 | Lead | Delivery | Caseの特徴 | Knowledgeの特徴 |
|---|---|---|---|---|
| 村上案件型 | 雲孫側の直接接点 | 雲孫 | BAAO関与なし。公開は完了後 | 顧客・雲孫知財があり、開始時には求めない |
| Enterprise共同提供型 | 会員側の既存接点 | 会員法人＋BAAO監修 | 許諾が重く、Liteが適する | 限定モジュールなら再利用余地あり |
| 外部Partner紹介型 | BAAOが新規紹介 | 外部パートナー | パートナーの営業価値が高い | 予約販売型を検証 |

社名、契約額、原価は実案件の条件ではない。類型比較のための合成ケースである。

### 2-2. 比較制度

| ID | 内容 |
|---|---|
| Current | 現行CBAA 12% / 5%＋Case＋Recipe、Referral 10% |
| v1.2 | Listing無料＋Recipe、ケース単体5万円、CD標準50万円、Referral 10% |
| V2初期 | 4取引分離。Case 6万/15万円、Commissioned 15万円、Knowledge 20万円＋20%または前払なし40% |
| V2修正 | Case作業上限とKnowledge最低保証を追加。将来資産価値込みで採択 |
| V2キャッシュガード | 取引別P10粗利率20%、粗利付きスコーピング料、Sponsored Case / Knowledgeの100%前受け |

### 2-3. 成立条件

CurrentからV2修正までは、次で成立判定した。

1. 提供者の効用が0円相当以上。
2. BAAOの即時収支と将来資産価値を合わせた総価値が0円相当以上。
3. CaseまたはKnowledgeでは、顧客が用途別に許諾する。

`旧BAAO総価値 = 即時キャッシュ − 運営原価 + Case資産価値 + Knowledge販売期待価値`

この条件では、将来価値で当面の赤字を隠せる。V2キャッシュガードでは次へ変更した。

`実現粗利 = 入金済み売上 − 著者報酬 − ロイヤリティ − 外注費 − 直接工数原価 − 見積・審査工数原価`

成立には、提供者効用、顧客許諾に加えて、前受け、実現粗利0円以上、粗利率20%以上が必要である。さらに不成立時も、見積・審査を開始する前にその原価へ20%の粗利を乗せたスコーピング料を受け取る。スコーピング料は返金せず、成約時だけ本体価格へ充当する。CaseやKnowledgeの将来価値は参考KPIとして別表示できるが、受注可否や黒字判定には使わない。

### 2-4. 主な仮説レンジ

| 項目 | 村上型 | Enterprise型 | 外部Partner型 |
|---|---:|---:|---:|
| 提供者時間単価 | 2〜3万円 | 2.5〜3.5万円 | 1.8〜2.8万円 |
| Case作業 | 5〜9h | 6〜12h | 5〜10h |
| Recipe作業 | 18〜30h | 24〜40h | 16〜30h |
| BAAO標準Case作業 | 8〜14h | 9〜16h | 8〜14h |
| Case用途別許諾率 | 65% | 55% | 72% |
| Knowledge用途別許諾率 | 20% | 30% | 50% |
| 100%前受け成立率 | Sponsored Case 25% | Knowledge 35% | Knowledge 40% |

BAAO運営原価は1.2万円/時間、不成立時の見積・審査は1〜3時間で試算した。スコーピング料は、Case審査1.5万円、Co-Delivery / Sponsored Case 3万円、Knowledge 4.5万円とし、それぞれ原価に対して20%の粗利を確保した。詳細レンジはJSONに保存した。

## 5. 制度に反映する修正

### 5-1. 残す

- Prime。
- 実在する新規紹介に対するReferral 10%・12か月。
- Case Editorによる事実確認。
- 個人・法人双方のクレジット。
- Yearbook等の可視化。ただし経済対価の代替にはしない。

### 5-2. 削除する

- CBAAの12% / 5%選択。
- `C`をBAAO実績へ「鞍替え」する概念。
- 無料掲載の条件としてのRecipe提供。
- 非公開案件を自動的に匿名Recipeへ転記する規定。
- Impact Pointsの残数通知、年次失効、Recipe寄稿による称号更新。
- P/C/R比率を追うKPI。
- 将来資産価値を通常取引の黒字判定へ入れること。
- 通常制度から赤字のCommissioned CaseやKnowledgeへ内部補填すること。

### 5-3. 置き換える

- `P / C / R` → `P / CD / L`。Rは紹介台帳のみ。
- CaseとKnowledgeの同意 → 用途別の独立Opt-in。
- Case → Lite 6万円 / Standard 15万円 / Sponsored 40万円前受け。
- Knowledge → 95万円または60万円の前受け成立後に制作。
- Impact Points → 非換金・非失効のActivity Ledger。
- Influenced Revenue → SOWのあるCo-Delivered案件総額だけ。
- 取引採択 → 実現粗利とP10粗利率20%の案件別審査。

## 6. 資金・受付ガード

通常制度の未回収制作費上限は0円とする。

- Sponsored CaseとKnowledgeは100%入金後に着手する。
- Co-Delivery Standardは70%前受け、残り30%を検収時とする。
- Verified Caseは100%前受けとする。
- 見積・権利確認は所定のスコーピング料入金後に開始し、不成立時も返金しない。成約時は本体価格へ充当する。
- 別案件のReferralや将来売上で赤字を相殺しない。
- BAAOが戦略的に無償コンテンツへ投資する場合は、本制度から切り離した取締役会承認済みの広報・研究開発予算で扱い、制度粗利へ含めない。

模擬パイロットではBAAO稼働が中央値56.2時間、P90で66.8時間だった。初回60日は次を上限とする。

- Case: 最大3件。Sponsored 1、Standard 1、Lite 1。
- Knowledge: 最大2件。
- Co-Delivery: 最大1件。
- 運営稼働: 64時間を計画上限とし、見込み超過時は新規受付を停止する。

P90は64時間を超えているため、同時に全件を受ける前提にはしない。案件開始前に残工数を再見積もりする。

## 9. 最終判定

模擬パイロットで確定できるのは、恒久価格ではなく制度の交換構造と、赤字を止める受付条件である。

BAAOは、案件を作ればReferral、品質を提供すればCo-Delivery、事例を検証・流通すればCase料金、知識を受け取れば著者へ対価、という双方向の市場になるべきである。同時に、将来のブランド価値や売上期待を理由に通常取引の赤字を認めてはならない。

全案件がCaseやKnowledgeになる必要はない。前受け、許諾、採算が揃わない取引を断ることが、制度の正常動作である。
