## 0. 結論

模擬パイロットの結果、制度構造は次で固められる。

1. 現行CBAAの12% / 5%は、新規適用を停止する。
2. Primeを残し、現行Cを`Co-Delivery`と`Member Case Listing`へ分割する。
3. Referralは10%・12か月を残すが、公開格付から外して紹介台帳にする。
4. Case ListingとKnowledge Asset Licenseを別契約・別同意・別対価にする。
5. Impact Pointsを称号更新のノルマから外し、無償のRecipe提供を求めない。

v1.2の「ケース＋レシピなら掲載無料、ケースだけなら5万円」は採用しない。今回のレンジでは全10,000回・全3類型で提供者がケース単体5万円を選び、Knowledge Assetは0件だった。さらにBAAOのケース審査・編集は中央値約11時間で、5万円経路のBAAO即時収支は案件別中央値で約▲8.2万〜▲10.0万円となった。

第1改善案もそのままでは不合格だった。Knowledgeの「20万円＋20%」と「前払なし＋40%」は提供者の執筆原価を補えず、ライセンス成立は0件。標準ケースも8時間上限を超えた。

そこで第2ラウンドでは、ケース編集のスコープ上限とKnowledgeの最低保証を追加した。修正版は3つの中止条件代理指標をすべて通過した。

- 公平感代理値: 中央値5.6 / 7
- 標準ケースのBAAO作業: 中央値8.0時間
- 配信SLA達成率: 95.2%
- 公開ケース期待値: 3件中1.72件
- Knowledge成立期待値: 最大2件中0.60件
- BAAO総価値: 3件合計中央値約137.4万円

一方、BAAO即時キャッシュは3件合計P10で約▲16.9万円になる。Commissioned CaseとKnowledgeは黒字の役務ではなく先行コンテンツ投資である。したがって、将来販売や紹介料を当てにせず、事前承認した投資予算を別枠で持つ必要がある。

## 1. 証拠と制約

### 1-1. 現行情報

- Brainbase Philosophy Contextを2026-07-16に再取得した。
- Graph SSOTの`org_baao`、`baao`、`unson`、`org_unson`を再確認した。
- BAAOは成功事例・レシピ・専門家監修・品質・流通を担い、雲孫は実装・運用の受け皿という役割分離を前提にした。
- BAAO / 雲孫には重複エンティティが残る。

したがって、人物の欲求、許諾率、工数、価格感応度はGraph Factではない。すべて制度比較用の明示的な仮説レンジである。

### 1-2. この結果から言えること

- 同じ仮説条件を制度ごとに比較したとき、どこで交換が不成立になるか。
- 料金とスコープの組み合わせが、提供者とBAAO双方の最低条件を満たすか。
- 許諾、運営工数、即時キャッシュのどれがボトルネックになるか。

### 1-3. この結果だけでは言えないこと

- 実在する山本氏、佐藤氏、会員、顧客が実際に同じ選択をすること。
- BAAO掲載が生む実商談価値。
- Knowledge Assetの実販売本数。
- 法務、税務、競争法上の妥当性。

恒久価格は、実在関係者への選択実験と実運用5件または60日の早い方で再判定する。

## 2. 模擬パイロットの設計

### 2-1. 3案件類型

| 類型 | Lead | Delivery | Caseの特徴 | Knowledgeの特徴 |
|---|---|---|---|---|
| 村上案件型 | 雲孫側の直接接点 | 雲孫 | BAAO関与なし。公開は完了後 | 顧客・雲孫知財があり、開始時には求めない |
| エンタープライズ共同提供型 | 会員側の既存接点 | 会員法人＋BAAO監修 | 許諾が重く、Liteが適する | 限定モジュールなら再利用余地あり |
| 外部パートナー紹介型 | BAAOが新規紹介 | 外部パートナー | パートナーの営業価値が高い | 最低保証付きロイヤリティを検証 |

社名、契約額、原価は実案件の条件ではない。類型比較のための合成ケースである。

### 2-2. 比較制度

| ID | 内容 |
|---|---|
| Current | 現行CBAA 12% / 5%＋Case＋Recipe、Referral 10% |
| v1.2 | Listing無料＋Recipe、ケース単体5万円、CD標準50万円、Referral 10% |
| V2初期 | 4取引分離。Case 6万/15万円、Commissioned 15万円、Knowledge 20万円＋20%または前払なし40% |
| V2修正 | 4取引分離に、Case作業上限、Knowledgeのスコープ縮小と最低保証、投資予算ガードを追加 |

### 2-3. 成立条件

各取引は次の3条件をすべて満たしたときだけ成立とした。

1. 提供者の効用が0円相当以上。
2. BAAOの即時収支と将来資産価値を合わせた総価値が0円相当以上。
3. CaseまたはKnowledgeでは、顧客が用途別に許諾する。

`提供者効用 = 金銭・配信・信用・監修価値 − 現金負担 − 作業原価 − 知財リスク`

`BAAO総価値 = 即時キャッシュ − 運営原価 + Case資産価値 + Knowledge販売期待価値`

総価値は会計売上ではない。コンテンツ投資判断の比較値である。

### 2-4. 主な仮説レンジ

| 項目 | 村上型 | Enterprise型 | 外部Partner型 |
|---|---:|---:|---:|
| 提供者時間単価 | 2〜3万円 | 2.5〜3.5万円 | 1.8〜2.8万円 |
| Case作業 | 5〜9h | 6〜12h | 5〜10h |
| Recipe作業 | 18〜30h | 24〜40h | 16〜30h |
| BAAO標準Case作業 | 8〜14h | 9〜16h | 8〜14h |
| Case用途別許諾率 | 65% | 55% | 72% |
| Knowledge用途別許諾率 | 20% | 30% | 50% |

BAAO運営原価は1.2万円/時間で試算した。詳細レンジはJSONに全件保存した。

## 3. 途中結果

### Round 1: 現行Handbook

| 指標 | 結果 |
|---|---:|
| 公開Case期待値 | 0.32 / 3件 |
| Knowledge期待値 | 0件 |
| 公平感代理値 | 2.8 / 7 |
| 公開時Case作業 | 中央値12.1h |
| 配信SLA | 63.6% |

村上型とEnterprise型では、提供者は全回で12%を選び、5%＋Case＋Recipeを選ばなかった。5%経路は現金が減っても、Recipeの執筆と知財リスクが大きいためである。

村上型の12%は提供者効用中央値が約▲7.4万円で、Case成立率は7.0%。Enterprise型は監修価値があるため提供者には成立しやすいが、BAAO即時収支が中央値約▲6.8万円だった。役務価格を別にせず、ケース資産価値で赤字を正当化している状態である。

一方、BAAOが本当に新規紹介した外部パートナー型のReferral 10%は成立率100%だった。現行制度を全廃するのではなく、具体的な案件供給に対応するReferralは残せる。

**判定: 不合格。** 公平感、8時間上限、配信SLAの3条件すべてに抵触。

### Round 2: v1.2

| 指標 | 結果 |
|---|---:|
| 公開Case期待値 | 1.73 / 3件 |
| Knowledge期待値 | 0件 |
| 公平感代理値 | 4.2 / 7 |
| 公開時Case作業 | 中央値11.4h |
| 配信SLA | 77.9% |

ListingとCo-Deliveryの分離により参加は改善した。しかし、3類型とも10,000回すべてで「ケース単体5万円」が選ばれた。無料にするためにRecipeまで提供する選択は0回だった。

5万円のCase Listingは、成立した案件でもBAAO即時収支が次のとおり赤字だった。

| 類型 | BAAO即時収支の中央値 |
|---|---:|
| 村上型 | 約▲8.2万円 |
| Enterprise型 | 約▲10.0万円 |
| 外部Partner型 | 約▲8.2万円 |

**判定: 構造は改善、交換設計は不合格。** Knowledgeが集まらず、ケース編集原価と配信約束が持続しない。

### Round 3: V2初期案

4取引を分離し、CaseをLite 6万円、Standard 15万円、Commissionedの著者謝礼15万円とした。Knowledgeは20万円＋20%、または前払なし＋40%とした。

結果、Caseと公平感は改善したが、Knowledge提供者の受諾率はEnterprise型、外部Partner型とも0%。標準Case作業も中央値8.6時間で上限超過した。

**判定: 不合格。** 売上連動廃止だけでは足りず、無償知識提供の問題を低い制作費へ置き換えただけだった。

### Round 4: V2修正版

Round 3を受けて次を変更した。

1. Verified Case LiteはBAAO作業3時間まで、6万円。
2. Verified Case StandardはBAAO作業8時間まで、15万円。
3. 8時間を超える原稿は提供者へ戻すか、追加見積またはCommissionedへ切り替える。
4. Knowledgeをフル秘伝書ではなく8〜16時間程度の再利用モジュールへ縮小する。
5. 固定型は著者40万円＋純売上20%。
6. ロイヤリティ型は純売上40%に加え、30万円の最低保証を設ける。
7. 16時間を超えるFull Playbookは個別SOWとし、Listingへ抱き合わせない。

最低保証型は、契約時に30万円を返還不要で支払い、累計純売上の40%が30万円を超えた分から追加ロイヤリティを支払う前提とした。

| 指標 | V2修正版 |
|---|---:|
| 公開Case期待値 | 1.72 / 3件 |
| Knowledge期待値 | 0.60 / 最大2件 |
| 商流取引の成立率 | 100% |
| 公平感代理値 | 5.6 / 7 |
| 標準Case作業 | 中央値8.0h |
| 配信SLA | 95.2% |
| BAAO即時キャッシュ | 中央値約29.8万円、P10約▲16.9万円 |
| BAAO総価値 | 中央値約137.4万円 |

**判定: 模擬パイロット通過。** ただし投資キャッシュのガードが必要。

## 4. 案件別のV2修正版結果

### 4-1. 村上案件型

| 取引 | 提案 | 結果 |
|---|---|---:|
| Lead | BAAO紹介なし | 紹介料なし |
| Delivery | 雲孫単独 | BAAO役務なし |
| Case | Commissioned、著者15万円 | 成立率48.0% |
| Knowledge | 開始時は求めない | 非提示 |

提供者受諾は100%だが、顧客許諾が65.8%、BAAO総価値の条件もあるため、約半数だけが公開に進む。これは失敗ではない。BAAOが価値を感じず、顧客が許可しない案件を無理に「BAAO実績」にしないことが制度の正常動作である。

Commissioned CaseのBAAO即時支出は中央値約28.0万円、総価値は中央値約11.1万円。編集委員が戦略価値を事前承認した案件だけに限定する。

### 4-2. Enterprise共同提供型

| 取引 | 提案 | 結果 |
|---|---|---:|
| Delivery | Co-Delivery標準50万円 | 成立率100% |
| Case | Verified Lite 6万円 | 成立率55.0% |
| Knowledge | Module 40万円＋20% | 成立率23.5% |

Co-Deliveryは提供者効用中央値約42.4万円、BAAO即時収支中央値約15.0万円で双方に成立した。Caseは提供者受諾100%だが、成立率は用途別許諾55%に支配された。

Knowledgeは提供者受諾92.0%まで改善したが、顧客許諾30.0%がボトルネックで成立率23.5%。知識価格より先に、顧客データや案件固有情報を除いた権利設計が必要である。

### 4-3. 外部Partner紹介型

| 取引 | 提案 | 結果 |
|---|---|---:|
| Lead | Referral 10%・12か月 | 成立率100% |
| Case | Verified Standard 15万円 | 成立率68.7% |
| Knowledge | 30万円最低保証・40% | 成立率36.5% |

Referralは、BAAOが新規接点を作った証拠がある場合には成立した。Caseは提供者受諾95.6%、顧客許諾72.0%。Standardを8時間で止めることで、BAAO即時収支は1件5.4万円となった。

Knowledgeは提供者受諾84.9%まで改善したが、許諾49.8%が上限となった。最低保証は「売れるか分からないのに作る」現在バイアスを緩和する一方、BAAOに約38.4万円の先行キャッシュ負担を生む。

## 5. 制度に反映する修正

### 5-1. 残す

- Prime。
- 実在する新規紹介に対するReferral 10%・12か月。
- Case Editorによる事実確認。
- 個人・法人双方のクレジット。
- Yearbook等の可視化。ただし経済対価の代替にはしない。

### 5-2. 削除する

- CBAAの12% / 5%選択。
- `C`をBAAO実績へ「鞍替え」する概念。
- 無料掲載の条件としてのRecipe提供。
- 非公開案件を自動的に匿名Recipeへ転記する規定。
- Impact Pointsの残数通知、年次失効、Recipe寄稿による称号更新。
- P/C/R比率を追うKPI。

### 5-3. 置き換える

- `P / C / R` → `P / CD / L`。Rは紹介台帳のみ。
- CaseとKnowledgeの同意 → 用途別の独立Opt-in。
- 5万円一律 → Lite 6万円 / Standard 15万円 / Commissionedの3経路。
- 無償Recipe → Knowledge Module 40万円＋20%、または30万円最低保証付き40%。
- Impact Points → 非換金・非失効のActivity Ledger。
- Influenced Revenue → SOWのあるCo-Delivered案件総額だけ。

条文レベルの修正案は`docs/internal/OPERATIONS_HANDBOOK_V2_AMENDMENT_PROPOSAL_2026-07.md`に分離した。

## 6. 投資予算と受付上限

V2修正版は将来総価値が正でも、即時キャッシュが常に正とは限らない。

| 投資枠 | 最大即時支出の目安 |
|---|---:|
| Commissioned Case 1件 | 著者15万円＋編集最大12h＝29.4万円 |
| Knowledge Module 1件 | 著者40万円＋審査最大10h＝52万円 |
| 最低保証型Knowledge 1件 | 保証30万円＋審査最大9h＝40.8万円 |
| 合計最大枠 | 122.2万円 |

初回60日では、将来売上やReferral入金を相殺せず、125万円をコンテンツ投資上限として事前承認する。予算がない場合はCommissionedとKnowledgeを開始しない。

模擬パイロットの3件をそのまま実運用する場合、BAAO稼働は中央値50.2時間、P90で62.6時間だった。60日枠は次を上限とする。

- Case: 最大3件。Commissioned 1、Standard 1、Lite 1。
- Knowledge: 最大2件。
- Co-Delivery: 最大1件。
- 月間担当可能時間を64時間確保できない場合は件数を減らす。

配信SLAは、最終公開承認からCaseページ10営業日、ニュースレター・公式SNS20営業日とする。BAAO都合で未達の場合は掲載料50%返金または全額相当の次回Caseクレジットを提供する。

## 9. 最終判定

模擬パイロットで確定できるのは、恒久価格ではなく制度の交換構造と初回運用条件である。

BAAOは「会員の売上から取る組織」ではなく、案件を作ればReferral、品質を提供すればCo-Delivery、事例を検証・流通すればCase料金、知識を受け取れば著者へ対価、という双方向の市場になるべきである。

全案件がCaseやKnowledgeになる必要はない。村上案件型で公開が約半数に留まることも、Enterprise型でKnowledge許諾が約4件に1件であることも、顧客と提供者の自律性を守った結果である。BAAOが集めるべきなのは強制された件数ではなく、役割、対価、許諾が揃った再利用可能な実績である。
