## 0. 結論

現行制度の問題は、単に12%や5%が高いことではない。BAAOが受け取る価値と、参加者へ返す価値を一つの「共ブランド制度」に束ね、参加者の主な報酬を名誉・ポイント・所属感に寄せていることである。

v1.2のListing / Co-Delivery / Prime分離は、売上連動と責任主体の問題を大きく改善する。一方、Case Listing無料経路に「ケース＋レシピ提供」を残すと、BAAOが再利用可能な知識資産を得る一方で、提供者は執筆工数、顧客許諾、知財流出を負担する。雲孫や成熟した外部企業には、自社で公開する選択肢もあるため、掲載・ポイント・Yearbookだけでは交換が成立しにくい。

制度のセンターピンは、次の4取引を分離し、取引ごとに「誰が、何を提供し、何を受け取り、どこまで責任を持つか」を明示することである。

1. Lead / Referral: 誰が案件機会を作ったか
2. Delivery / Quality: 誰が顧客成果と品質を担ったか
3. Case Verification / Distribution: 誰が事例を検証・編集・流通させたか
4. Knowledge Asset License: 誰の知見を、どの条件で再利用・販売するか

称号、ポイント、Yearbook、コミュニティ所属は補助報酬としては機能する。しかし、金銭・案件機会・具体的な流通コミットメント・知識資産への対価を代替させてはならない。

## 2. Graph SSOTから確認した制度上の前提

### 2-1. BAAOと雲孫は役割が異なる

Graph上、BAAOは教育、普及、コミュニティ、倫理、標準化、人のエンパワーメントを担う。雲孫は実行、実装、運用、制作のレイヤーである。BAAOの組織情報にも、雲孫は実装・運用の受け皿として記載されている。

したがって、雲孫が獲得・提供した案件をBAAOが無条件に「BAAO実績」と扱うことも、逆にBAAOが案件に関与したというだけで雲孫へ無条件に流すこともできない。案件ごとにLead、Delivery、Case、Knowledgeの寄与を分けて記録する必要がある。

### 2-3. Graph品質上の注意

- BAAOは `org_baao` と `baao` の重複候補がある。
- 雲孫も `unson` と `org_unson` の重複候補がある。
- NEC、Growin Partnersにも顧客エンティティの重複がある。
- BAAOプロジェクトの一つは `code=baao` だが名称が空欄である。
- 個人所属の一部に議事録由来の未確認情報が混在する。

このため、制度確定後には組織、顧客、プロジェクト、役割の重複整理が必要である。

## 3. 現行制度とv1.2で残る構造問題

### 3-1. 現行Handbook

現行C案件は、会員が契約主体となり、原則PC 12%を拠出する。代替としてPC 5%に加えケースとレシピを提供する。Handbookはこの設計に「努力正当化と名誉（公開）の交換でPCの痛みを中和」と記載し、P/C/Rラベル、Impact Points、目標勾配、損失回避、Yearbook等を参加心理として組み込んでいる。

問題は次のとおり。

- BAAOが案件を供給していなくても売上連動負担が発生する。
- 5%経路では現金に加えてケース・レシピ制作と知財提供が必要になる。
- ポイントは個人に付くが、顧客許諾、執筆工数、知財流出は所属企業も負う。
- 年次失効や称号維持が知識提供と結び付くと、任意貢献が実質的義務に近づく。
- BAAOが受け取る再利用資産に対し、参加者が得る案件機会や流通量は保証されない。

### 3-2. v1.2で改善したこと

- C案件をCase ListingとCo-Deliveryに分離した。
- BAAOの役務が事前合意された場合だけCo-Deliveryを名乗る。
- Prime、Referralを別制度として扱う。
- 売上12%/5%の新規適用を凍結する方向にした。
- 村上案件は雲孫を契約・提供主体の基本とし、BAAO役務がある場合のみSOWを付ける整理にした。

### 3-3. v1.2で未解決のこと

無料Listingの標準経路をケース＋レシピ提供とした点で、知識資産ライセンスと掲載サービスがまだ結合している。Impact Points、称号、Yearbookもほぼ現行のままである。

この状態では「掲載してもらうために知見を渡す」制度になる。掲載の価値が不確実な参加者ほど自社発信を選び、BAAOが最も欲しい成熟事例が集まらない逆選択が起きる。

## 4. N=1ペルソナ

同一人物でも、BAAO理事、雲孫代表、個人専門家では合理的な選択が異なる。そのため、人格ではなく役割単位でペルソナを分離した。

### P1. 山本力弥 / BAAO代表

- Graph Fact: BAAO代表理事、AI戦略コンサルタント。
- 欲求仮説: BAAO名義の案件・実績を増やし、ブランドと収益基盤を可視化したい。
- 恐れ仮説: 会員がBAAOを使わず直取引し、BAAOが交流会だけになること。
- 参加条件: BAAOの具体的寄与とリターンが台帳で見える。
- 離脱・強硬化条件: 外部で生まれた案件がすべてBAAO外に流れ、資産も収益も残らない。
- 注意: 「BAAOの実績になるなら直でもよい」は意向として不自然ではないが、現行制度には直案件を実績化する公平な交換条件がない。

### P2. 佐藤圭吾 / BAAO理事・技術判断者

- Graph Fact: BAAO理事、生成AIエキスパート、技術判断を担う。
- 欲求仮説: BAAOに高品質な方法論と再現可能な成功事例を蓄積したい。
- 恐れ仮説: 低品質な事例がBAAO名義で公開され、専門家としての信用を毀損すること。
- 参加条件: 審査基準、責任範囲、監修工数の対価が明確。
- 離脱条件: 無償監修が常態化し、技術責任だけが残る。

### P3. 佐藤圭吾 / 雲孫代表

- Graph Fact: 雲孫CEO/CTO。雲孫はBAAOとは別の実装・運用レイヤー。
- 欲求仮説: 顧客成果と粗利を守り、事例が次の案件獲得につながること。
- 恐れ仮説: 自力獲得案件から売上、顧客関係、方法論をBAAOへ移し、見返りが曖昧になること。
- 外部代替: 雲孫名義で公開・営業・再利用できる。
- 参加条件: BAAOの配信、信用、案件紹介、監修等の追加価値が具体的で、雲孫と担当者の帰属が残る。
- 離脱条件: BAAO実績化が雲孫の粗利・主導権・知財を薄める。

### P4. 独立専門家 / Fellow候補

- 根拠: 既存WebペルソナのFellow像と、Graph上の外部パートナー群を合成。特定個人の事実ではない。
- 欲求仮説: 信用、肩書、案件機会、専門性の可視化、仲間。
- 恐れ仮説: 無償労働、評価基準の不透明さ、運営者との距離による案件格差。
- 外部代替: note、SNS、自社サイト、他コミュニティで発信可能。
- 参加条件: 小さな初回貢献、署名、案件導線、透明な選定、現金または明確なサービス価値。
- 離脱条件: ポイントだけ増え、案件や信用に変換されない。

### P5. 外部実装会社

- 根拠: Graph上の複数パートナー企業を合成。特定企業の意向ではない。
- 欲求仮説: 案件、共同受注、信用補完、採用・営業に使える実績。
- 恐れ仮説: BAAOに顧客を迂回される、独自ノウハウを失う、責任境界が曖昧になる。
- 参加条件: リード帰属、顧客所有、再利用範囲、紹介料、共同提供範囲が契約で明確。
- 離脱条件: BAAOがブランド料だけ取り、営業・品質・運営を提供しない。

### P6. 卯田剛史 / コミュニティマネージャー

- Graph Fact: BAAOコミュニティマネージャー。
- 欲求仮説: 新規参加と継続の両方を増やし、会員同士の助け合いを可視化したい。
- 恐れ仮説: 制度が複雑・不公平に見え、関係性の調整が個人に集中すること。
- 参加条件: 参加者へ一文で説明でき、例外時のエスカレーション先がある。
- 離脱条件: ポイントや称号への不満をコミュニティ運営が感情労働で吸収する。

### P7. 小川未来 / オペレーション

- Graph Fact: BAAOのオペレーションを担う。
- 欲求仮説: 迷いなく審査、契約、公開、分配、更新を処理できる。
- 恐れ仮説: 無料掲載が増え、編集、許諾、監修、台帳更新の工数だけが膨らむ。
- 参加条件: 成果物、SLA、予算、RACI、受付上限が定義されている。
- 離脱条件: 例外判断が代表・理事・運営の口頭合意で増え続ける。

### P8. 顧客事業責任者

- 根拠: Graph上のNEC、Growin案件の顧客側意思決定者を抽象化。個別企業の意向ではない。
- 欲求仮説: 成果、社内説明、採用・広報効果、信頼できる提供体制。
- 恐れ仮説: 未承認の社名・数値公開、責任主体の曖昧さ、失敗の固定化。
- 参加条件: 公開範囲を選べ、公開前確認と撤回条件が明確。
- 離脱条件: 契約時に事例化が抱き合わせになっている。

### P9. 顧客法務・広報承認者

- 根拠: 顧客組織で公開許諾を担う役割の合成人格。
- 欲求仮説: リスクを限定し、承認履歴を残す。
- 恐れ仮説: 二次利用、AI学習、方法論販売、永続掲載が一つの同意で処理されること。
- 参加条件: 社名、成果数値、素材、販売利用、AI利用を分けて同意できる。
- 離脱条件: 一度許諾すると撤回不能、または利用範囲が読めない。

## 5. シミュレーション方法

### 5-1. 行動効用

各ペルソナは、次の合計が外部代替より高い場合に参加すると仮定した。

`参加効用 = 金銭 + 案件機会 + 信用 + 学習/所属 + ミッション適合 - 工数 - 現金負担 - 責任リスク - 知財/顧客流出 - 自律性低下`

各項目を0〜3で評価し、役割ごとの優先度で重み付けした。比較スコアは -8〜+8 に丸めた。

- +4以上: 参加可能性が高い
- +1〜+3: 条件付き参加
- 0: 外部代替と同程度
- -1〜-3: 原則見送り
- -4以下: 強い拒否または迂回行動

重みは1（低）〜3（高）。負担側の列は高いほど、同じ負担に強く反応する。

| Persona | 金銭 | 案件 | 信用 | 所属/使命 | 工数負担 | 責任リスク | 知財/自律性 |
|---|---:|---:|---:|---:|---:|---:|---:|
| P1 BAAO代表 | 3 | 3 | 3 | 3 | 2 | 3 | 2 |
| P2 BAAO理事・技術 | 2 | 2 | 3 | 2 | 3 | 3 | 3 |
| P3 雲孫代表 | 3 | 3 | 3 | 1 | 2 | 3 | 3 |
| P4 独立専門家 | 2 | 3 | 3 | 3 | 2 | 2 | 2 |
| P5 外部実装会社 | 3 | 3 | 3 | 1 | 2 | 3 | 3 |
| P6 コミュニティ | 1 | 2 | 2 | 3 | 3 | 3 | 1 |
| P7 オペレーション | 1 | 1 | 1 | 2 | 3 | 3 | 2 |
| P8 顧客事業責任者 | 2 | 2 | 3 | 1 | 2 | 3 | 2 |
| P9 顧客法務・広報 | 1 | 1 | 3 | 1 | 2 | 3 | 3 |

重み自体も仮説である。選択実験では、選択結果だけでなく「何を最も失いたくないか」を聞き、重みを更新する。

### 5-3. 適用した行動仮説

| 行動仮説 | 今回の制度で起きること | 設計上の扱い |
|---|---|---|
| 外部代替 | 自社公開・直接契約が簡単な人ほどBAAO参加の要求水準が高い | 不参加を罰せず、追加価値で選ばれる |
| 現在バイアス | 執筆・許諾の負担は今発生し、案件機会は将来かつ不確実 | 曖昧な露出ではなく、納品・対価を具体化 |
| 損失回避 | 年次ポイント失効は継続を促す一方、無償貢献を断りにくくする | 活動履歴と知識提供を切り離す |
| 目標勾配 | 次の称号まで少しだと活動が増える | 品質・学習には使えるが、寄付ノルマには使わない |
| 地位欲求 | 署名、称号、Yearbookは個人に効く | 法人が負担する工数・知財の対価には数えない |
| 曖昧性回避 | 二次利用・販売・AI利用の範囲が不明だと顧客と企業は拒否する | 権利と同意を用途別に分ける |
| 保有効果 | 自社方法論は、外から見た相場より本人が高く評価する | 一律ポイントで買わず、価格と権利を個別合意 |
| 返報性 | BAAOが先に具体的な審査・配信・案件機会を出すと貢献が返りやすい | 双方向の納品を同じ台帳に置く |
| 主人・代理人問題 | 個人が称号を得て、所属企業が工数と知財を負担する | 個人と法人を二重帰属させ、双方の承認を取る |
| 公平性選好 | 料率より、役員企業や近い人だけが有利に見えることが離脱を招く | リード配分、COI、審査理由を記録する |

これらは行動を断定する診断ではない。選択実験で反証可能な仮説として扱う。

## 6. シミュレーション途中経過

### Round 0: 対照ケースを置く

**入力**: 雲孫や外部実装会社は、自力案件を自社名義で契約し、自社媒体で公開できる。

**途中結果**:

- 実装会社は粗利、顧客関係、知財を保持できる。
- 個人専門家もSNSやnoteで署名付き発信ができる。
- BAAOには収益、実績、レシピ、関係データが残らない。
- したがって、BAAO制度は「参加しない場合の不利益」ではなく、外部代替を上回る追加価値を作る必要がある。

**発見**: BAAOの競合は他団体だけではなく、自社公開と直接契約である。

### Round 1: PC 12%を適用

**入力**: BAAOが案件を供給していない自力獲得案件にも12%が発生すると仮定。

**役割別反応**:

- 雲孫代表: BAAOの役務が見えないため拒否。雲孫直を選ぶ。
- 外部実装会社: 粗利を守るため制度外契約を選ぶ。
- 独立専門家: BAAOブランドが強く、12%以上の受注増が期待できる場合のみ検討。
- BAAO代表: 1件あたり収益は魅力だが、参加件数が減る。
- コミュニティ/運営: 例外説明と関係調整の負担が増える。

**途中結果**: 短期の案件単価は上がるが、自力で案件を取れる人ほど離れる。BAAOに残るのはブランド依存度の高い案件に偏る。

**失敗理由**: 売上料率とBAAOの具体的役務が連動していない。

### Round 2: PC 5%＋ケース＋レシピへ変更

**入力**: 現金負担を下げる代わりに、事例と再利用可能な知識を提供。

**役割別反応**:

- 雲孫代表: 5%に加え、許諾、執筆、方法論流出が発生。12%より総負担が重くなる案件では拒否。
- 独立専門家: 初期の信用形成には魅力があるが、案件実績が増えるほど知見供与の機会費用が高くなる。
- BAAO理事: 事例とレシピが蓄積する点は魅力。ただし監修工数が増える。
- 顧客承認者: ケース掲載とレシピ販売の利用範囲が一体だと許諾しにくい。
- オペレーション: 5%計算、成果確認、ケース編集、レシピ審査、販売分配を同時管理する。

**途中結果**: 「現金を払うか、知見を渡すか」という選択に見えるが、実際には5%も残る。価値ある知見を持つ人ほど離れ、経験の浅い人ほど名誉・ポイントを選びやすい。

**失敗理由**: 交換する資産の価格と権利が明示されず、ケース掲載と知識ライセンスが抱き合わせになっている。

### Round 3: v1.2 Listing / Co-Delivery分離を適用

**入力**: 売上連動を凍結し、完了案件のListingと、有償役務を提供するCo-Deliveryを分ける。無料Listingはケース＋レシピ提供。

**役割別反応**:

- 雲孫代表: 売上連動がなくなり大幅改善。ただしレシピ提供に対する確実なリターンがなければ、自社公開を選ぶ。
- 独立専門家: 署名、称号、Yearbookに価値を感じる層は参加する。
- 外部実装会社: BAAOからの配信量や案件導線が読めず、条件付きまたは見送り。
- BAAO代表/理事: 役務と責任が整理され、運営判断はしやすくなる。
- オペレーション: 無料経路が増えるほど編集原価が予算化されていない問題が残る。
- 顧客承認者: 完了後の任意掲載になった点は改善。レシピ利用許諾は引き続き分離が必要。

**途中結果**: v1.2は契約・責任の構造を改善するが、貢献インセンティブは「露出・称号・ポイント」に依存したまま。個人には効いても、企業が負担する顧客許諾・知財・工数を回収できない。

**発見**: 個人への評判報酬と、企業への経済・知財対価を別々に設計しなければならない。

### Round 4: 4取引を分離した改善案を適用

**入力**: Lead、Delivery、Case、Knowledgeを別契約・別同意・別台帳にする。参加者は取引ごとに参加を選べる。

**役割別反応**:

- 雲孫代表: 顧客と知財を維持しつつ、具体的な配信や案件導線が得られるならCaseを選ぶ。Knowledgeは別対価で判断。
- 独立専門家: 現金、サービスクレジット、案件優先、署名・称号から自分に合う組み合わせを選べる。
- 外部実装会社: 紹介・共同提供・事例公開を独立判断できるため参加しやすい。
- BAAO代表: 収益は売上連動一律ではなくなるが、案件供給、審査、編集、ライセンスという実際の価値に対応する。
- BAAO理事: 無償監修ではなく、品質役務として工数を計上できる。
- オペレーション: 取引数は増えるが、標準SOW・同意・台帳で例外を減らせる。
- 顧客: CaseとKnowledgeを別々に許諾でき、匿名化・撤回条件も選べる。

**途中結果**: 成熟した実装会社、個人専門家、顧客の参加条件が同時に成立しやすくなった。ただし、選択肢を増やしすぎると説明と運用が複雑になる。

**修正**: 外向けには4つの取引名だけを見せ、価格・権利の選択肢は各取引内で最大2〜3個に制限する。

### Round 5: 悪用・破綻ストレステスト

| 想定される行動 | 制度が壊れる理由 | 追加するガード |
|---|---|---|
| 低品質事例を大量投稿して露出だけ得る | 編集・審査原価が運営へ転嫁される | 証拠基準、固定審査枠、差戻し上限、必要なら審査料 |
| BAAOが「配信する」とだけ約束する | 参加者が得る価値を測れない | 掲載面、ニュースレター、イベント等の具体的納品を明記 |
| 案件由来リードを運営者の近い人へ流す | 公平性と継続意欲を壊す | 発生元、優先提示先、辞退履歴、紹介料を台帳化 |
| 顧客が公開許諾を撤回する | 永続掲載前提だと紛争化する | 撤回・匿名化・販売停止の手順と期限を契約化 |
| 役員企業が有利な配分を受ける | 利益相反でブランドを毀損する | COI申告、審査・配分からの忌避、議事記録 |
| 称号更新のために無償レシピを出させる | 自発的貢献が強制労働化する | 称号更新と知識寄付を切り離す |
| 個人は称号を得るが所属企業は損をする | 社内承認が通らず、後で関係が壊れる | 個人クレジットと法人貢献台帳の二重帰属 |
| 「残り枠」を恣意的に煽る | 偽の希少性になる | 実際の審査能力に基づく受付数だけを表示 |
| 失敗事例を公開した人の評価を下げる | 学習共有が止まる | 誠実な失敗共有を減点しない。違反と学習を分離 |

**途中結果**: 金銭メニューだけでは安定しない。帰属、COI、顧客同意、運営容量のガードが同じくらい重要である。

### Round 6: キャッシュ採算ストレステスト

Round 4の改善案をMonte Carloで再検証したところ、公平感、Case作業上限、配信SLAは通過したが、3案件合計の即時キャッシュがP10で約▲16.9万円となった。Commissioned Caseと2つのKnowledgeメニューも案件別P10で赤字だった。

原因は、将来のCase資産価値とKnowledge販売期待価値をBAAOの採択条件へ足し、Referral等の黒字で赤字取引を相殺したことである。そこで次へ修正した。

- 将来資産価値を通常取引の採算判定から除外する。
- 不成立時の見積・審査工数も原価へ含める。
- 成立取引ごとにP10粗利0円以上、P10粗利率20%以上を求める。
- Sponsored CaseとKnowledgeは100%前受け後に制作する。
- 見積・権利確認前に、原価へ20%の粗利を乗せた返金不可のスコーピング料を受け取り、成約時は本体価格へ充当する。
- 案件間の損益を相殺しない。

修正後は、3案件合計の実現粗利がP10約68.7万円、成立取引の最低P10粗利率が20.0%となった。不成立を含む全提示導線でもP10・平均とも粗利0円以上となり、採算条件を通過した。ただし前受け率、工数、価格は合成仮説であり、実パイロットで更新する。

## 8. 推奨する制度構造

### 8-1. Lead / Referral

- BAAOが案件を発見、適格化、紹介した場合だけ紹介料を設定する。
- 料率、対象期間、対象売上、既存接点、再紹介を契約で定義する。
- 事例から発生したリードは、原則として事例提供者へ先に提示する。
- 提供者が辞退した場合のみ、能力・利益相反を見て他会員へ回す。
- 現行GCV 10%は仮置きで維持可能だが、実運用データで再検証する。

### 8-2. Delivery / Quality

- BAAOが元請になるPrimeと、他社案件へ役務提供するCo-Deliveryを分ける。
- 監修、QA、PM、方法論提供をSOWにし、固定額または工数で価格化する。
- 「BAAO共同提供」は開始前に役務・責任・表示を合意した案件だけが使える。
- BAAO役員や専門家の監修工数を無償前提にしない。

### 8-3. Case Verification / Distribution

- Case ListingとRecipe提供を切り離す。
- 案件提供者は、実名、匿名、非公開を選べる。
- 顧客は、社名、ロゴ、数値、コメント、販売利用を個別に許諾できる。
- BAAOが提供する価値を「サイト掲載」だけでなく、審査、編集、QR、ニュースレター、イベント紹介等の納品物で示す。
- 費用モデルは次の二つまでに絞ってパイロットする。
  - Verified Case: 提供者が審査・編集の固定費を100%前払いする。
  - Sponsored Case: 提供者または第三者スポンサーが制作費を100%前払いする。
- BAAO自身が戦略上欲しい事例を買う場合は、通常制度と損益を分離した広報・研究開発予算で事前承認する。
- 無料掲載の条件としてRecipeを要求しない。

### 8-4. Knowledge Asset License

- Recipe、テンプレート、プロンプト、評価基準、研修素材はCaseと別資産として扱う。
- 利用範囲を、会員閲覧、研修利用、販売、改変、AI学習に分ける。
- 対価メニューは、販売先または予約者から制作原価とP10粗利率20%を満たす金額を100%前受けできた場合だけ提示する。
- 前払なしのロイヤリティのみは標準メニューにしない。
- サービスクレジットを選べる場合は、円換算と利用期限を明示する。
- 既存Handbookの執筆者40%分配は出発点にできるが、制作工数、前受け率、販売確率を測り、案件別粗利と著者対価の双方を再判定する。

### 8-5. 評価・称号・帰属

- Impact Pointsを、報酬通貨ではなく活動履歴へ格下げする。
- 称号更新をRecipe提供や無償労働と結び付けない。
- 専門性の称号は、品質、顧客評価、審査、倫理遵守で更新する。
- 個人には署名と専門家プロフィール、所属企業には法人貢献実績を付ける。
- ケースにはLead、Delivery、Supervision、Case Author、Knowledge Authorを別表示する。
- BAAOが提供していない案件は「BAAO会員による実績」とし、「BAAO実績」「共同提供」と混同しない。

## 9. 村上案件への当てはめ

ユーザーから共有された実案件の経緯では、村上氏との接点は雨宮氏の会で直接生まれ、佐野氏は偶然関連会社の存在を知っていた程度で、紹介者としての関与は薄い。この経緯はGraph Factではなく、案件当事者からの観察情報として扱う。少なくとも現時点では、佐野氏またはBAAOへの紹介料を自動発生させる根拠にはならない。

現時点の基本形は次のとおり。

1. 雲孫が契約・提供主体になる。
2. BAAOが監修、QA、方法論、PMを提供する場合だけCo-Delivery SOWを付ける。
3. 案件完了後、村上氏側の許諾と成果確認が取れた場合のみCase Listingを検討し、LiteまたはStandardを100%前払いする。
4. BAAOまたは第三者がフル制作を求める場合は、Sponsored Caseの制作費を100%前払いする。
5. Recipe化はCase Listingと別に、佐藤・雲孫・顧客の権利を確認してライセンスする。
6. 表示は実際の役割に合わせ、「雲孫提供」「BAAO共同提供」「BAAO会員による実績」を使い分ける。

なお、雲孫をBAAOの法人会員として扱う正式なGraph Factまたは規約は、今回確認できていない。会員扱いを制度の前提にする前に明文化が必要である。

## 10. 人間心理を検証する選択実験

### 10-1. 対象

- BAAO代表・理事: 2〜3名
- 運営: コミュニティ、オペレーション、コンテンツから各1名
- 雲孫: 経営、案件担当の2視点
- 独立専門家: 経験年数の異なる3名
- 外部実装会社: 2社
- 顧客側: 事業責任者と法務・広報を各2名

### 10-2. 聞き方

理想を聞くのではなく、実際の案件を置いて選ばせる。

**実装会社向け選択**

A. 5万円で審査・編集・掲載

B. Recipeを提供すれば無料掲載

C. BAAOを使わず自社公開

D. BAAOがニュースレター、イベント、リード優先提示まで約束するなら有料掲載

選択後に「その条件でも参加をやめる一線」を聞く。

**専門家向け選択**

A. Impact Pointsと称号のみ

B. 固定制作費

C. 販売ロイヤリティ

D. サービスクレジット＋署名＋案件優先

金額を段階的に変え、Willingness to Acceptを測る。

**顧客向け選択**

A. 実名・成果数値あり

B. 社名あり・数値レンジ

C. 業界名のみ匿名

D. 非公開

CaseとKnowledge販売を別質問にし、抱き合わせによる見かけの同意を避ける。

### 10-3. 必須質問

1. どの選択肢を選ぶか。
2. 何が一つ変われば別の選択になるか。
3. 誰の承認が必要か。
4. 最も失いたくないものは何か。
5. 参加しない場合、代わりに何をするか。
6. 公平でないと感じる箇所はどこか。

## 11. 60日パイロット

### Phase 0: 2週間 / 計測準備

- 4取引の一枚説明を作る。
- Case同意、Knowledgeライセンス、Co-Delivery SOW、Referralの最小タームを作る。
- RACIとCOI申告を定義する。
- Graphの組織・顧客重複を整理する。
- Personal KGを再認証し、関係者の既存選好を確認する。

### Phase 1: 3件 / 模擬選択

- 雲孫直案件: 村上案件を想定。ただし完了前に実績掲載しない。
- BAAO関与案件: NECまたはGrowinの既存案件から、許諾可能なものを選ぶ。
- 外部パートナー案件: 独立専門家または実装会社から1件。

各案件でLead、Delivery、Case、Knowledgeを別々にYes/No判断し、誰がどの条件で断ったかを記録する。

### Phase 2: 30日 / 小規模実運用

- 公開Caseは最大3件に制限する。
- Knowledge Assetは最大2件に制限する。
- Co-Deliveryは最大1件でSOWを試す。
- 受付枠は実際の審査・編集能力から設定する。
- Sponsored CaseとKnowledgeは100%前受け、Verified Caseは100%前受け、Co-Delivery Standardは70%前受けとする。
- 見積・権利確認は、Case 1.5万円、Co-Delivery / Sponsored Case 3万円、Knowledge 4.5万円の返金不可スコーピング料入金後に開始する。成約時は本体価格へ充当する。
- 通常制度の未回収制作費を0円にする。

### 計測項目

| 指標 | 目的 |
|---|---|
| 各取引の参加率 | どの交換が成立したか |
| 断り理由 | 価格、知財、工数、信用のどこが障害か |
| 提供者の実作業時間 | 無料貢献の隠れ原価 |
| 審査・編集・許諾の実作業時間 | BAAO側原価 |
| 不成立時の見積・審査工数 | 失注原価を含む採算把握 |
| 取引別の入金・直接原価・粗利・粗利率 | 案件別黒字の確認 |
| 提示導線別のスコーピング料・失注粗利 | 不成立時も赤字にしない確認 |
| 前受け提示率・成立率 | 資金条件の受容性 |
| 顧客許諾率とリードタイム | 公開の実現可能性 |
| 配信実績と流入 | 掲載価値の実測 |
| 事例由来の商談・受注 | 案件機会の価値 |
| 公平感 7段階 | 継続可能性 |
| 60日後の継続意思 | 制度の実効性 |
| 撤回・苦情・COI件数 | 倫理・ガバナンス |

### 中止・再設計条件

- 公平感が中央値4未満。
- 1件の審査・編集が8時間を継続して超える。
- 配信納品が約束どおり実行できない。
- 3案件合計の実現粗利P10が0円未満。
- 成立取引にP10粗利0円未満またはP10粗利率20%未満のメニューがある。
- 不成立を含む提示導線にP10粗利0円未満、または平均粗利0円未満のメニューがある。
- 通常制度に未回収制作費が発生する。
- 知財または顧客帰属で1件でも重大な認識相違が起きる。
- 参加者が称号維持のために断りづらいと回答する。
- 役員・近接企業への利益配分でCOIを解消できない。

## 12. 倫理ガードレール

行動心理は参加を強制するためではなく、価値を理解しやすくし、良い選択を小さく始められるように使う。

- 各取引は個別Opt-in。会員資格との抱き合わせをしない。
- 断っても称号、案件配分、コミュニティ関係で報復しない。
- デフォルト設定と利用範囲を明示し、簡単に撤回できる。
- 実在しない希少性、権威、社会的証明を作らない。
- 金銭・サービス価値を名誉だけで代替しない。
- 公開範囲、台帳公開、署名は本人・法人・顧客の同意を分ける。
- 失敗共有と品質違反を区別する。
- 運営者、役員企業、近親者の利益相反を記録し、審査・配分から外す。

## 15. 最終評価

山本氏の「BAAOの実績になるなら直でもよい」という欲求そのものはおかしくない。BAAOを持続可能な組織にするには、実績、収益、知識資産が残る必要がある。

おかしいのは、その欲求を満たす手段として、自力獲得案件の売上やレシピを一律に求め、見返りを名誉・ポイント・曖昧な露出に寄せることである。これは人間の欲を追えていないのではなく、BAAO側の欲だけを制度化し、参加者、所属企業、顧客、運営の欲と恐れを同時に扱えていない。

あるべき姿は、BAAOが価値を提供した箇所で対価を得て、BAAOが価値を受け取った箇所では提供者へ対価を返す、双方向の市場設計である。称号と所属感はその交換を温めるが、交換そのものの代わりにはならない。
