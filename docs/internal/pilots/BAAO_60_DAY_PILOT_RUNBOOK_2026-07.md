# BAAO制度改定 60日実パイロット実施要領

- 作成日: 2026-07-17
- ステータス: 実施準備。制度・料金の本承認ではない
- 対象案: `../OPERATIONS_HANDBOOK_V2_AMENDMENT_PROPOSAL_2026-07.md`
- 模擬結果: `../BAAO_INCENTIVE_PILOT_SIMULATION_2026-07.md`

## 1. 今回確かめること

模擬パイロットでは、前受けとスコーピング料を入れた案がキャッシュ採算条件を通った。ただし、前受け率、提示受容、実工数は仮説である。実パイロットでは次の4点だけを確かめる。

1. 実在の関係者が、Lead、Delivery、Case、Knowledgeを別々の取引として理解し、自由に選べるか。
2. 標準価格のまま、実際にスコーピング料または本体料金を払う意思があるか。
3. 失注工数を含めても、取引別に赤字にならず、完了取引で粗利率20%以上を残せるか。
4. BAAOの実績や称号を餌にせず、提供者、BAAO、顧客の3者が公平だと感じられるか。

参加者数や公開件数を増やすことは目的にしない。無償作業、案件間の赤字相殺、将来価値の先取りは行わない。

## 2. 実施前ゲート

次が揃うまで、有料スコーピングと本体役務を開始しない。

- [ ] 制度分離、初回価格、前受け、受付上限についてBAAOの承認者が記録を残した。
- [ ] Scoping Order、Referral、Co-Delivery、Case、Knowledgeの必要契約を法務確認した。
- [ ] 入金、返金、著者報酬、ロイヤリティの会計・税務処理を確認した。
- [ ] パイロットOwner、採算判定者、COI時の代替承認者を指名した。
- [ ] 台帳の保存先と閲覧権限を決めた。
- [ ] Case掲載とKnowledge利用の顧客許諾フォームを用意した。
- [ ] 価格例外、無償制作、未回収制作費を機械的に止める運用を確認した。

このゲートの未完了は「需要がない」ではなく「実施準備未完了」として扱い、0件に集計しない。

## 3. 対象と上限

### 3-1. 選択インタビュー

Graph SSOTと会員台帳から、次の3類型を各2〜3者選ぶ。個人名、所属、案件関係は実施直前にGraphで再確認し、レポート内の合成人物を実在人物として扱わない。

| 類型 | 確かめる心理 | 主に提示する選択肢 |
|---|---|---|
| 自力獲得する会員・会員法人 | 自案件の主導権、顧客関係、実績表示への欲求 | Case。BAAO役務が必要な場合だけCo-Delivery |
| 大企業側の実務家 | 社内承認、品質保証、再現可能な方法論への欲求 | Co-Delivery、Case、Knowledgeを別々に提示 |
| 外部パートナー | 紹介対価、自社名義、知財収益への欲求 | 新規接点がある場合だけReferral。Case、Knowledgeは別提示 |

村上案件型は「雲孫が直接獲得・提供した案件」の候補であり、Referral対象にしない。案件完了前はCaseを売らず、顧客許諾の見込みが立ってから提示する。雲孫をBAAO法人会員として表示できるかは別決裁とする。

### 3-2. 有料枠

- Sponsored Case: 1件。
- Verified Standard: 1件。
- Verified Lite: 1件。
- Knowledge Asset: 2件。
- Co-Delivery: 1件。
- BAAO運営稼働: 合計64時間。
- 未回収制作費: 0円。

枠が埋まった場合は、実在する受付上限として説明してよい。ただし、締切や競争を演出して即決を迫らない。

## 4. 標準フロー

```text
候補確認
  → Lead Originを証拠で分類
  → 標準提示カードを同条件で提示
  → 2営業日以上の検討期間
  → 辞退 / 保留 / 選択を台帳へ記録
  → 必要な取引だけScoping Order締結・入金
  → 役務・権利・許諾・COI・採算を確認
  → No-Go / 条件付きGo / Go
  → 本体契約・必要前受け
  → 納品
  → 許諾、表示、配信
  → 実工数・原価・粗利・公平感を確定
```

### 4-1. 候補確認

1. Graph SSOTと一次資料で、人、組織、会員状態、案件主体を確認する。
2. Lead Originator、Contracting Entity、Delivery Entityを別々に記録する。
3. BAAOが作った新規接点の証拠がなければReferralを提示しない。
4. 案件開始後にBAAO関与を足してCo-Delivery表示へ変更しない。

### 4-2. 提示

1. `BAAO_PILOT_OFFER_CARD_2026-07.md`を先に渡し、口頭説明で条件を上書きしない。
2. 「どれも選ばない」「まだ決めない」を必ず読み上げる。
3. 断っても会員上の不利益がないことを説明し、台帳へ確認を残す。
4. 標準価格に対する反応を測るため、担当者判断の非公開値引きをしない。
5. 値引き要望は拒否理由として記録し、その場で価格を下げない。
6. 候補確認、提示、初回説明、回答記録の実時間を、辞退を含む全件で`offer_hours`へ記録する。

### 4-3. スコーピング

1. 見積、権利確認、顧客許諾確認を始める前に、Scoping Orderを締結する。
2. Case 2.3万円、Co-Delivery / Sponsored Case 3.8万円、Knowledge 5.3万円を入金後に着手する。
3. BAAOが作業開始前に受付を断る場合は返金する。合意作業開始後は不成立でも返金せず、本体成立時は価格へ充当する。
4. 実工数と直接原価を記録し、本体不成立で単独完了した場合も粗利率20%以上かを確定する。
5. No-Goの理由を`rights_not_cleared`、`coi_blocked`、`margin_below_floor`、`scope_mismatch`等で残す。

### 4-4. 本体契約と納品

1. CaseとKnowledgeは100%、Co-Delivery Standardは70%の前受けを確認してから本体作業を始める。
2. 直接工数は作業当日に記録する。後から予算時間へ丸めない。
3. スコープ上限へ80%到達した時点で、縮小、追加見積、停止のいずれかを決める。
4. CaseとKnowledgeは顧客・権利者の許諾が取れなければ公開・販売しない。
5. 表示は契約・提供主体とBAAOの役割を分け、BAAOが保証していない範囲を明記する。

## 5. 週次運用

### 毎週

- 新規提示、辞退、保留、スコーピング、本体進行を台帳へ反映する。
- `node scripts/validate-baao-pilot-ledger.mjs <ledger.csv>`を実行する。
- 取引別の提示、スコーピング、納品の実工数、売上、直接原価、実現粗利を確認する。
- 未回収制作費、COI、苦情、断りにくさの兆候を確認する。
- 稼働見込みが64時間を超える場合は新規受付を止める。

### 2週ごと

- 類型別の提示数、受諾数、拒否理由を比較する。
- 担当者ごとの説明差、値引き、追客回数を監査する。
- 成立取引のP10はサンプルが少ない間は参考値とし、個別赤字を平均で隠さない。提示導線は終了提示3件から累計貢献利益で判定する。
- 条件変更は次の提示から適用し、提示済み案件へ不利に遡及しない。

## 6. 判定基準

### 6-1. 即時停止

次のどれかが起きたら新規受付を止め、既存案件の保護対応だけを行う。

- 完了取引が赤字、または同一`offer_variant`の終了提示が3件以上になった時点で提示獲得原価を含む累計貢献利益が赤字。
- 完了取引の粗利率が20%未満。
- 本体不成立で単独完了した有料スコーピングの粗利率が20%未満。
- 本体作業の前受け不足または未回収制作費が発生。
- 公平感中央値が4未満。
- 「断ると称号や案件配分で不利になる」との回答が1件でもある。
- Knowledgeの権利範囲で重大な認識相違が発生。
- 解消できないCOI、顧客無許諾の公開、未解決の重大苦情が発生。
- 稼働が64時間を超える見込み。

### 6-2. メニュー別シグナル

| 結果 | 判定 |
|---|---|
| 適格な標準提示3件で有料スコーピング0件 | 需要シグナルなし。価値提案か対象を見直し、安易に値下げしない |
| 標準価格で有料スコーピング1件以上 | 支払意思の初期シグナルあり |
| 完了1件、粗利率20%以上、重大苦情なし | 暫定通過。恒久価格の証拠としては不足 |
| 完了3件以上がすべて黒字、公平感中央値4以上 | メニュー継続候補 |
| 同一提示導線の終了提示3件以上で、提示獲得原価を含む累計または1提示あたり平均貢献利益が赤字 | 新規提示を止め、価格、対象、工程を再設計 |

小標本で「市場に受け入れられた」と断定しない。60日終了時は、継続、条件修正、停止のいずれかをメニュー別に決める。

## 7. 60日後の決裁資料

次を1つの実行レポートへまとめる。

1. 類型別・メニュー別の提示、辞退、保留、受諾。
2. 拒否理由の原文と分類。個人を責める表現は除く。
3. スコーピングと本体の実工数分布。
4. 入金、直接原価、実現粗利、粗利率。
5. 顧客許諾率、許諾日数、配信SLA。
6. 公平感、苦情、COI、撤回。
7. 模擬パイロットの仮定値と実測値の差。
8. Handbookへ採用する条項、修正する条項、廃止する条項。

決裁はメニュー単位で行う。Caseが通ったからKnowledgeも通す、Referralが儲かったから赤字のCaseを残す、といった抱き合わせはしない。
