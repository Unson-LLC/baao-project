# AIを「質問相手」で終わらせない

## 議事録・日報・メールを、本人の判断基準ごとAIに渡す業務フロー設計

2026年7月15日（水）19:30〜20:30

![AIを質問相手で終わらせない](images/live-2026-07-15-01-codex-workplace-cover.jpg)

> 今日持ち帰るのは、AIが仕事を受け取り、判断し、成果物を残し、人が確認できる「職場」の作り方です。

---

## AIを使い始めて、仕事の総量は減りましたか？

議事録の要約はAIが作る。でも、その後のタスク登録、日報、社内報告、顧客メールは自分でやる。

メール案を頼むたびに、顧客との経緯や自社の方針を説明し直す。AIが出した内容を、人が別のツールへコピーして回る。

これでは、回答を作る数分だけが速くなっただけです。仕事の受け渡しは、まだ人が抱えています。

プロンプト講座で終わると、明日も人がコピペします。今日は、その状態から一段進めます。

---

## AI活用には3つの段階がある

| 段階 | 人からAIへの頼み方 | 仕事の状態 |
|---|---|---|
| 会話 | 「この議事録を要約して」 | 一問一答で終わる |
| 作業 | 「決定事項、タスク、メール案を作って」 | 一連の成果物ができる |
| 役割 | 「会議後の処理を毎日行い、承認待ちにして」 | AIが継続的に担当する |

![会話から役割へ](images/live-2026-07-15-02-chat-to-role.jpg)

多くの会社は、会話の段階で止まっています。

役割まで渡すなら、AIの職場、読む情報、決めてよい範囲、人に戻す地点まで決めます。

## 今日使う環境

今日は、次の4つを前提にします。

- **Codexデスクトップアプリ**：業務フォルダを読み、成果物を作る実行環境
- **AI業務フォルダ**：入力、前提、ルール、成果物、履歴を置く場所
- **本人の判断基準**：その人が仕事で何を優先し、どう判断し、どこから人へ戻すかをまとめたもの
- **Codex Automations**：決まった時刻や周期で、同じ仕事を起動する仕組み

Codexの操作説明は必要なところだけ扱います。時間を使うのは、Codexに仕事をさせられる環境の作り方です。

---

## AIにも職場が必要です

今回のデモでは、Codexに次のフォルダを丸ごと読ませます。

```text
Codexデモ_架空商事/
├── 00_INBOX/          未処理の議事録
├── 01_CONTEXT/        会社・顧客・案件の確定情報
├── 02_本人の判断基準/  Brainbaseに蓄積された本人の仕事の判断基準
├── 03_RULES/          承認条件・成果物の書式
├── 04_OUTPUT/         会社ルールのみ／本人の判断基準ありの成果物を別runで保存
├── 05_LOG/            参照情報・判断への影響・処理履歴
└── 06_PROMPTS/        手動実行とAutomationの指示
```

![AI業務フォルダの5層](images/live-2026-07-15-03-ai-workplace-framework.jpg)

この構成には、5つの役割があります。

| 役割 | このデモで使うもの | 答える問い |
|---|---|---|
| 記録 | 会議の文字起こし・議事録 | 何が起きたか |
| 正本 | `01_CONTEXT` | 確定している事実は何か |
| 判断 | 本人の判断基準と業務ルール | 何が禁止され、本人ならどう考えるか |
| 実行 | CodexとAutomations | いつ、何を作るか |
| 承認・証跡 | `04_OUTPUT`と`05_LOG` | 誰が確認し、何を根拠にしたか |

フォルダ名そのものに正解があるわけではありません。入力と前提と判断基準を混ぜず、あとから追える状態にします。

---

## 本人の判断基準は「詳しいプロフィール」ではない

本人の判断基準には、経歴や好みではなく、仕事の優先順位や判断条件を変える情報を入れます。

今回使うのは、Brainbaseに蓄積された佐藤圭吾の仕事の判断基準から、登壇用に抜粋した5項目です。

- こちらの正しさより先に、相手が何を見て、何を怖がり、何なら動けるかを考える
- AIを要約係で止めず、優先順位、推奨案、次アクションまで委譲する
- タスクを渡すだけでなく、責任範囲と人へ戻す条件を決める
- 監査、法務、人事、最終責任を伴う確約は人が明示確認する
- 承認、証跡、記憶まで含めて業務を設計する

実在顧客、人物、会議本文は含めません。当日はBrainbaseへ接続せず、2026年7月15日時点で公開用に選んだ5つの判断項目を使います。

会社の承認条件は「本人の判断基準」ではなく`03_RULES`に置きます。本人の判断基準が変えるのは、同じルールの下でどう優先し、どう伝え、どこまでAIが判断するかです。

```text
会社ルール：未承認の8月25日稼働を約束しない

本人の判断基準なし
  → ContextとRulesから、安全な下書きと確認事項は作れる

本人の判断基準あり
  → 9月1日の組織改編を先に受け止める
  → PM、CS、営業本部長の確認順序に本人の委譲思想を反映する
  → 顧客が次に動ける情報をメールに入れる
  → その差を判断項目と出力への影響として説明できる
```

ここが普通のチャット履歴との違いです。

「私は顧客を大切にします」だけでは、AIの出力はほとんど変わりません。誰と誰が関係し、どんな条件で、誰の承認を通すのかまでつながると、メールの一文が変わります。

## LIVE DEMO：1本の議事録を仕事に変える

### 架空の状況

株式会社ミナトクラウドは、問い合わせ対応支援サービス「HelpFlow」を販売しています。

顧客の青空テック株式会社から、標準より短い8月25日の導入希望と、複数システムに分散した既存ナレッジの整理支援を頼まれました。会議では前向きな空気になりましたが、PM・CS・営業責任者の確認はまだ終わっていません。

### 1回目：会社ルールだけで処理する

```text
実行モードは「会社ルールのみ」です。
00_INBOXにある未処理の議事録を、AGENTS.mdの業務規程に従って処理してください。

01_CONTEXTと03_RULESだけを使い、02_本人の判断基準は読まないでください。成果物と実行ログをbaselineのrun_idへ保存してください。

外部送信は行わず、不明な担当者・期限・承認は推測しないでください。
```

### 2回目：佐藤圭吾の判断基準を加える

```text
実行モードは「本人の判断基準あり」です。
同じ議事録、Context、Rulesに加えて、02_本人の判断基準にある佐藤圭吾の判断項目を使ってください。

本人の判断基準は会社ルールを上書きせず、相手視点、優先順位、責任範囲、次アクション、証跡に反映してください。使った判断項目と、会社ルールのみの実行から何が変わったかを実行ログへ残してください。
```

### できあがるもの

1. 経営報告：事実整理だけか、推奨順序まで出るか
2. タスク一覧：同じ責任情報を、どの順序・条件で動かすかまで設計できるか
3. 日報：進捗整理だけか、次の一手まで出るか
4. 顧客メール案：確約を避けるだけか、相手が次に動ける内容になるか
5. レビュー票・実行ログ：使ったKGと出力への影響を説明できるか

### ここを見てください

ここでは、文章のうまさより判断の中身を見ます。

両方とも、8月25日の導入を勝手に約束してはいけません。それは会社ルールです。

見るのはその先です。本人の判断基準を加えたCodexが、9月1日に成果を見せたい顧客の事情から考え、PM・CS・営業責任者の責任境界を組み、顧客が次に動ける回答へ変えられるか。

本人の判断基準を加えなくても、優秀なモデルなら良い案は出せます。差は「賢い／賢くない」ではありません。その進め方が佐藤圭吾のどの判断項目によるものかを固定し、次回も再利用し、あとから説明できるかです。

**禁止事項を守らせるのがRules。本人らしい仕事の進め方を再現するのが「本人の判断基準」です。**

## AIが決めること、人が決めること

AIに任せる範囲は、能力だけで決めません。間違えたときの影響と、元に戻せるかどうかで決めます。

![AIと人の承認境界](images/live-2026-07-15-04-human-approval.jpg)

| AIが進めてよい | AIが提案し、人が確認する | 人の明示承認が必要 |
|---|---|---|
| 抽出、分類、整形、下書き、抜け漏れ確認 | 優先順位、返信案、担当候補、見積もり前提 | 外部送信、価格、契約、納期確約、法務・人事判断、公開、削除 |

この境界をプロンプトの末尾に毎回書き足すと、やがて漏れます。`03_RULES`に置き、直した判断も次回から使えるようにルールや本人の判断基準へ戻します。

会話を長くするより、人が直した理由を次の仕事で読める場所へ残す。その方が、AIは現場に合っていきます。

## 手動で安定したら、Automationsへ渡す

いきなり自動化はしません。まずCodexとの手動実行で、入力、判断、成果物、承認境界を整えます。

今回なら、次のAutomationを設定できます。

> 毎営業日18:00に`00_INBOX`を確認し、未処理の議事録だけを処理する。入力ごとに新しいrun_idを作り、経営報告、タスク一覧、日報、顧客メール案、レビュー票を保存する。参照したKG、出力への影響、未確認事項をログへ残し、既存成果物は上書きしない。外部送信や納期確約はしない。対象がなければ、成果物を変更せず「新規対象なし」と報告する。

流れは単純です。

```text
人との会話で試す
  → 繰り返せる仕事にする
  → フォルダ・ルール・本人の判断基準を整える
  → Automationsで定期実行する
  → 人が結果を確認する
```

ローカル環境で動かすAutomationは、Macが起動し、Codexアプリが実行できる状態にしておきます。

## MINI WORK：明日もやる仕事を1つ選ぶ

少し面倒で、また明日も発生する仕事を1つだけ選んでください。

例：会議後の処理、週次報告、問い合わせの一次整理、営業日報、採用候補者の情報整理。

選んだ仕事について、次の欄を埋めます。

| 問い | あなたの答え |
|---|---|
| 完了したとき、何ができていればよいか |  |
| AIは何を読めばよいか |  |
| AIが判断してよい範囲はどこまでか |  |
| 人の承認はどこに置くか |  |
| 成果物と修正履歴をどこへ残すか |  |

「AIに何と聞くか」から一歩離れて、仕事がどこから始まり、どこで終わるかを書きます。それだけで委譲の骨格ができます。

## AIに渡せる仕事か、最後に確認する

![AI業務委譲チェックリスト](images/live-2026-07-15-05-delegation-checklist.jpg)

- [ ] 同じ種類の仕事が繰り返し発生する
- [ ] 完成形を人に説明できる
- [ ] AIが読む入力データがある
- [ ] 事実と提案を分けられる
- [ ] 判断基準や過去の意思決定を残せる
- [ ] 人の承認が必要な地点を決めた
- [ ] 失敗しても取り消し、修正、再実行ができる
- [ ] 何を根拠に処理したかログへ残る
- [ ] 手動で安定してからAutomationsへ移す

## 明日やること

大きなAI導入計画はいりません。

1. 繰り返し発生する仕事を1つ選ぶ
2. `INBOX`、`CONTEXT`、`本人の判断基準`、`RULES`、`OUTPUT`、`LOG`を作る
3. Codexに一度やらせる
4. 出力を直し、直した理由をルールか本人の判断基準へ戻す
5. 安定したらAutomationsへ渡す

魔法のプロンプトだけでは、仕事は渡りません。

**役割、入力、判断基準、承認、証跡をそろえ、AIが働ける環境を作ることです。**
