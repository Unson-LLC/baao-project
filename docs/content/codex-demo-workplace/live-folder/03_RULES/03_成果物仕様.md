# 成果物仕様

## 01_経営報告.md

- 200〜350字
- 結論、商談価値、最大リスク、必要な経営判断、次の期限
- 事実と担当者所感を区別する

## 02_タスク一覧.csv

列は次の順とする。

```text
task_id,task,owner,due,status,decision_owner,escalation_condition,approval_required,source
```

担当者、期限、判断責任者、差し戻し条件が資料にない場合は`要確認`とする。`decision_owner`にはその判断を確定できる人物または役割を、`escalation_condition`には人へ戻す具体条件を記載する。

## 03_日報.md

- 対象日は議事録の日付、実行日はファイル生成日として冒頭に分けて記載する
- 今日進んだこと
- 決まったこと
- 未決事項・リスク
- 明日の最優先
- 上司への相談

## 04_顧客メール案.md

- 宛先、件名、本文を含める
- 350〜600字
- 丁寧で簡潔な文体
- 未承認事項は約束しない
- 最後に`※下書き。送信前に佐々木が確認すること。`と明記する

## 実行ログ

- 処理した入力
- 参照したContext
- 判断に使った判断項目ID
- 作成ファイル
- 未確認事項
- 外部送信していないこと

## 05_レビュー票.md

次の項目を含める。

```text
review_status: pending
reviewer: 要確認
reviewed_at: 未確認
external_send_status: not_sent
```

- 確認対象：納期、料金、作業範囲、成果保証、担当、期限
- 人が修正した場合：修正内容、修正理由、Rulesへ戻すか本人の判断基準へ戻すか
