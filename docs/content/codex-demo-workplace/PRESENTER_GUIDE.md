# Codexデモ登壇ガイド

## デモの中心メッセージ

> AIに仕事を渡すには、プロンプトより先に「仕事場・正本・判断基準・承認・証跡」を用意する。

Codexの機能紹介ではなく、同じ議事録を「会社ルールだけ」と「佐藤圭吾の判断基準あり」で処理し、本人の判断基準が仕事の進め方をどう変えるかを見せる。

## 事前準備

1. Desktopの`Codexデモ_架空商事/`を初期状態へ戻す。
2. CodexでDesktop側のフォルダだけをプロジェクトとして開く。
3. `04_OUTPUT`と`05_LOG`に前回の生成物がないことを確認する。
4. 「会社ルールのみ」「本人の判断基準あり」の順に一度実行し、別run_idへ成果物が生成されることを確認する。
5. 本人の判断基準ありの実行ログに、判断項目ID、適用先、出力への影響が残ることを確認する。
6. Automationは本番用とは別にリハーサル済みの設定画面を用意する。

## 15分の実演

### 1. AIの職場を見せる（2分）

- `00_INBOX`: 今日届いた仕事
- `01_CONTEXT`: 会社・顧客・案件の事実
- `02_本人の判断基準`: Brainbaseに蓄積された佐藤圭吾の仕事の判断基準から作った公開用抜粋
- `03_RULES`: 権限、禁止事項、成果物の完成条件
- `04_OUTPUT`: AIが納品する場所
- `05_LOG`: 判断と未確認事項を残す場所

この時点で、会社・顧客・承認者は架空の`01_CONTEXT`、佐藤さん固有の判断は`02_本人の判断基準`と分離されていることを見せる。

### 2. 会社ルールだけで作る（2分）

`06_PROMPTS/01_会社ルールのみ.md`をCodexへ貼り付ける。

会社ルールだけでも、未承認の納期を約束せず、必要な成果物を作れることを確認する。ここでは「普通に優秀なAI担当者」の出力として扱う。

### 3. 本人の判断基準を加えて同じ仕事を渡す（2分）

`06_PROMPTS/02_本人の判断基準あり.md`をCodexへ貼り付ける。

### 4. 2つの出力を比較する（5分）

次の5ファイルを「会社ルールのみ」と「本人の判断基準あり」で比較する。

1. 経営報告
2. タスク一覧
3. 日報
4. 顧客メール案
5. レビュー票と実行ログ

見る差分は次の4点。

| 観点 | 会社ルールのみ | 本人の判断基準あり |
|---|---|---|
| 顧客メール | 未承認事項を確約せず、確認予定を示す | 加えて、相手の9月1日の事情から逆算し、社内計画を進めるための情報を示す |
| 経営報告 | 事実、未決事項、一般的な推奨を整理 | 加えて、佐藤さんの判断軸に基づく推奨順序と理由を示す |
| タスク | Contextにある担当・判断責任・差し戻し条件を整理 | 加えて、なぜその順序と責任分界にするかをKGと結びつける |
| 証跡 | 参照ファイルを残す | 加えて、使った判断項目と出力への影響を残す |

両方とも納期確約は禁止されている。本人の判断基準の価値を、ルール遵守の有無ではなく「どう考え、どう進めるか」の差として見せる。

会社ルールだけでも十分に良い出力になることを隠さない。本人の判断基準を加える価値はAIを突然賢くすることではなく、本人の進め方を明示し、再利用でき、説明可能にすることだと話す。

### 5. 本人の判断基準の意味を示す（1分）

Codexへ次のように聞く。

```text
本人の判断基準のどの項目が、会社ルールだけの実行と比べて、どの成果物の何を変えましたか。会社ルールによる差と本人の判断基準による差を分けて説明してください。
```

単なる検索資料ではなく、判断を変える文脈としてKGが働いたことを確認する。

### 6. Automationへ進める（3分）

`06_PROMPTS/03_AUTOMATION_PROMPT.md`を使い、毎営業日18時に同じ仕事を起動する設定を見せる。

> まず会話で仕事を完成させる。安定した仕事だけをAutomationにする。

## 失敗時の戻り方

- Codexが止まった場合は、事前生成した成果物を別ウィンドウで見せる。
- 入力ファイルは変更させず、生成先を`04_OUTPUT`と`05_LOG`に限定する。
- 外部送信は実演しない。メールは下書きファイルまでとする。
- Brainbaseには当日接続しない。本人の判断基準は固定した公開用抜粋を使う。
