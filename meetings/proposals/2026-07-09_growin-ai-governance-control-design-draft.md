## 1. 結論

グローウィン様の社内AI化で最初に扱うべきテーマは、個別AIツールやナレッジAIではなく、**AI時代の情報ガバナンスと権限設計**である。

6月24日の議論では、ナレッジAI、タレントインタビュー、パフォーマンスブリーフィング、AI駆動コンサル/FDEなどを候補に置いた。その中で最も強い反応があったのはAIガバナンスだった。

理由は、AIを実務に入れようとすると、すぐに以下で止まるためである。

- 誰がどの情報を見てよいのか
- AIがその情報を参照してよいのか
- Google Drive、HubSpot、ATS、人事/財務データの既存権限をどこまで踏襲するのか
- Claude、ChatGPT、Gemini、Copilot、Claude Code、Codex、MCP/API接続を誰に許可するのか
- AI生成物を誰がレビューし、どこまで外部送信してよいのか
- AI活用の成果を、作成物ではなくどのアウトカムで見るのか

提案の言い方は「AIガバナンスを作りましょう」より、次がよい。

> AIが強力な業務実行者になった今、まず情報ガバナンスと組織権限を見直しませんか。
> その上で、AIにどこまで任せ、どこで人間がレビューし、どのアウトカムを追うかを設計しましょう。

### 実現できること / ROI

AIガバナンスを整える価値は、規程を作ること自体ではない。情報の流れ、会議体、意思決定、AI利用範囲を再設計し、会社運営のスピードと再現性を上げることにある。

| 実現できること | ROIの見方 |
|---|---|
| 情報の流れが整理される | 必要な情報が、必要な人とAIに届く。議事録探索、資料作成、社内確認、二重説明の時間を減らす |
| AI活用が安全に速くなる | 使ってよい情報、使ってよいAI、レビューが必要な場面が明確になり、情報漏えい/誤送信を抑えながらAI導入を進められる |
| 会社運営の型が外販資産になる | 会議体、コミュニケーション、意思決定、AIレビューの型を作ることで、社内実証をクライアント向けサービスに転用しやすくなる |

## 2. 提案コンセプト

### 名称案

**Corporate AI Control Design**

または

**AI時代の情報ガバナンス再設計**

### 一言で言うと

グローウィン様の組織・業務・情報権限を棚卸しし、AIが安全かつ実務的に使える権限、レビュー、外部送信、コミュニケーション、会議体、アウトカム管理の型を作る。

### 設計原則

| 原則 | 内容 |
|---|---|
| 既存権限を起点にする | Google Drive、CRM、人事、財務などの既存権限をAI利用にも踏襲する。ただしAIは横断推論できるため、例外領域を別途定義する |
| 全社員一律にしない | 一般AI利用、部門利用、Claude Code/Codex/MCP/API接続、管理者利用を分ける |
| アウトプットではなくアウトカムで見る | 資料やダッシュボードの量ではなく、準備時間短縮、提案品質向上、判断速度向上などで評価する |
| 情報の流れを設計する | 誰が、いつ、どの会議体で、どの情報を見て、何を決めるかをAI利用とセットで設計する |
| 人間レビュー点を明示する | 顧客提案、人事/採用、財務、契約/法務、経営判断はレビュー点を置く |
| 小さく始めてテンプレート化する | 社内で試し、運用できる型にしてからクライアント向けサービスへ転用する |

佐藤の個人KGでも、AI導入支援では「派手なAIツールより、業務内で使える環境、ポリシー、ガバナンス、オンボーディングを先に作る」ことが繰り返し出ている。権限設計は、全員で合意形成するより、責任者が共通ベースラインを作り、各部門責任者へ段階的に移譲する方が速い。

## 3. 設計の骨子

### 3.1 情報カテゴリ

| 区分 | 例 | AI利用方針の初期案 |
|---|---|---|
| 公開情報 | Webサイト、公開記事、公開セミナー資料 | 原則利用可 |
| 社内一般情報 | 社内制度、業務手順、公開済み社内ナレッジ | 社内AIで利用可 |
| 部門限定情報 | 部門会議録、部門KPI、案件管理情報 | 部門権限内で利用可 |
| 顧客情報 | 顧客名、提案書、議事録、商談履歴 | 用途、権限、外部送信基準を個別定義 |
| 個人情報 | 採用候補者、社員情報、評価、給与 | 原則制限。利用時は目的、権限、ログ必須 |
| 財務/経営機密 | 予算、粗利、人件費、経営会議資料 | 経営/限定メンバーのみ。AI接続は個別承認 |
| 法務/契約情報 | 契約書、紛争、法務相談 | AI利用範囲を限定。外部送信は原則禁止 |
| AI生成物 | 要約、提案書案、分析レポート | 外部送信前レビュー必須 |

### 3.2 AI利用レベル

| レベル | 対象者 | 利用範囲 | 主な制限 |
|---|---|---|---|
| L0: 閲覧のみ | AI利用対象外の社員 | AI生成物の閲覧 | AIへの直接入力不可 |
| L1: 一般利用 | 全社員または広範囲 | 文章作成、要約、一般調査 | 機密/個人情報入力不可 |
| L2: 業務利用 | 部門責任者、AI推進者 | 部門ナレッジ、議事録整理、業務支援 | 部門権限内データのみ |
| L3: 高度利用 | AI推進チーム、技術担当 | Claude Code、Codex、MCP、API接続 | 利用ログ、レビュー、権限申請必須 |
| L4: 管理者利用 | 経営、情シス、情報管理責任者 | 権限設計、監査、全体管理 | 操作ログと承認必須 |

7月9日では、L3以上を誰に許可するか、L2とL3の境界をどこに置くか、誰が権限付与/剥奪を行うかを確認したい。

### 3.3 SaaS接続時の確認観点

| 観点 | 確認内容 |
|---|---|
| 接続元/接続先 | どのAIが、Google Drive、HubSpot、ATS、会計、人事給与等に接続するか |
| 権限 | 利用者本人の権限で動くか、サービスアカウントで動くか |
| 保存/学習 | 会話、生成物、中間データがAI側に残るか。モデル学習に使われない設定か |
| ログ | 誰が、いつ、何にアクセスしたか残るか |
| 外部送信 | AIベンダーや外部APIへ送信されるか |
| 例外処理 | 権限外データを扱いたい場合の承認フロー |

短期は既存SaaS権限を踏襲する。中期では、複数SaaS横断が必要になった時だけ、データレイク/統合DB/権限一元管理を検討する。

### 3.4 人間レビューと外部送信基準

| 種別 | 例 | レビュー基準 |
|---|---|---|
| 社内メモ | 議事録要約、タスク整理 | 作成者または部門内レビュー |
| 社内判断資料 | KPI分析、採用候補比較 | 部門責任者レビュー |
| 顧客向けドラフト | 提案書、メール、ホワイトペーパー | 担当者 + 上長レビュー |
| 契約/法務/人事/財務 | 契約文案、評価、給与、採用判断 | AIは補助。専門責任者レビュー必須 |
| 経営判断 | 投資判断、撤退判断、組織変更 | AIは情報整理まで。最終判断は経営 |

### 3.5 コミュニケーション / 会議体 / 会社運営

AIガバナンスを実務で機能させるには、権限表だけでは足りない。どの情報が、どの会議体に入り、誰が見て、誰が決め、どのAIが補助するかまで設計する必要がある。

| 設計対象 | 初期論点 |
|---|---|
| コミュニケーションプラン | AI要約、会議ログ、タスク、意思決定事項をどこに流すか。Slack/Google Docs/社内AI等の使い分け |
| 会議体設計 | 経営会議、部門会議、プロジェクト会議、AI推進会議の入力/出力/参加者/頻度/決定事項 |
| 意思決定ルール | AIが整理する範囲、人間が判断する範囲、エスカレーション条件、レビュー責任者 |
| 会社運営案 | 情報収集、論点整理、判断、実行、振り返りが回る運営サイクル。将来的な外販時の診断観点にもする |

## 4. 世界のAIガバナンスの今

2026年6月時点では、世界のAIガバナンスは「倫理原則」から「運用可能な管理システム」へ移っている。

| 領域 | 現状 | グローウィン様向けの示唆 |
|---|---|---|
| EU | AI Actが段階適用中。禁止AI、AIリテラシー、GPAI、透明性、高リスクAIの義務が順次発効 | AI台帳、リスク分類、透明性表示、GPAIベンダー管理を成果物に入れる |
| 米国 | 連邦は安全保障/イノベーション寄り。NIST AI RMFは任意枠組みとして継続。州法は個別に進む | 一律法対応より、NIST準拠、州法/業界規制、説明責任への備えが重要 |
| 英国 | 包括法ではなく、既存規制当局が原則を適用するプロイノベーション型 | 法務調査だけでなく、業界別説明責任とAI保証を組み合わせる |
| 日本 | AI事業者ガイドライン第1.2版。ソフトロー、チェックリスト、自主的ガバナンスが中心 | 日本企業向けには、ガイドラインとISOをベースに棚卸しするのが現実的 |
| ASEAN/シンガポール | 生成AI、Agentic AI、AI Governance Guideなど実装ガイド型が進む | データ、説明責任、テスト、セキュリティ、コンテンツ来歴を入れる |
| 韓国/中国 | 韓国はAI基本法、中国は生成AI/アルゴリズム/ディープシンセシスを個別規制 | 高影響領域、生成物表示、情報安全、個人情報保護を意識する |
| 国際/標準 | OECD、G7 Hiroshima Process、UN、ISO/IEC 42001/23894/42005が共通語になりつつある | AI管理システム、AIリスク管理、AI影響評価を提案成果物にできる |

規制対応で共通化している実務は、以下に収束している。

- AI利用台帳
- リスク分類
- AI影響評価
- データ、権限、来歴管理
- 透明性表示/ラベリング
- 人間監督と外部送信基準
- ログ、監査、インシデント対応
- AIベンダー/GPAIモデル管理
- AIリテラシーとオンボーディング

したがって、本件は「法務調査」だけで売るより、**AI時代の情報ガバナンスを実務に落とす支援**として売る方がよい。法令適合性の最終判断は弁護士/専門家レビュー領域として切り分け、BAAOは業務設計、権限設計、運用テンプレート、AI活用実装側を担う。

## 5. 初期3ヶ月プロジェクト案

### 目的

グローウィン様のAI活用を止めている情報権限、データ接続、レビュー基準、コミュニケーション、会議体の論点を整理し、社内実証と外販サービス化の両方に使える型を作る。

単なる資料作成ではなく、議事録/業務ログを使って実態を把握し、AI・データガバナンスの設計を会社運営に組み込むところまでを初期プロジェクトの対象とする。

### 期間

基本は3ヶ月。初回の議事録/業務ログ分析の開始時期と、グローウィン様側のレビュー速度によっては、全体設計の完了まで4〜5ヶ月を見込む。

### 進め方

| フェーズ | 期間目安 | 内容 |
|---|---:|---|
| 1. 立ち上げ/データ取得設計 | 1ヶ月目 | 組織図、部門ミッション、利用SaaS、既存情報管理ルールを確認。Google Meet等の既存議事録/業務ログをAIで分析できる状態にする |
| 2. 業務実態分析/情報流通整理 | 1〜2ヶ月目 | 議事録/業務ログをもとに、部門別の業務、情報利用、会議体、人間関係/意思決定の詰まりを整理する |
| 3. ガバナンス/会社運営設計 | 2〜3ヶ月目 | 情報カテゴリ、AI利用レベル、SaaS接続方針、レビュー/外部送信基準に加え、コミュニケーションプラン、会議体、意思決定ルールを設計する |
| 4. 実装/外販化整理 | 3ヶ月目 | 必要に応じてAIツール/MCP権限ツール等への組み込み方針を整理し、会社運営案とクライアント向け診断/設計メニューに転用する |

### 実行体制

| 役割 | 担当 | 内容 |
|---|---|---|
| 全体設計/方針整理 | BAAO | AI・データガバナンス設計、提案方針、成果物レビュー |
| 分析/実装支援 | BAAO支援メンバー | 議事録/業務ログ分析、データ整理、AIツール/MCP等の実装補助 |
| 社内業務理解/調整 | グローウィン様側アサインメンバー | 社内会議体、業務実態、人間関係、例外運用、コミュニケーション導線の把握。各部門との調整 |
| AI/データ接続確認 | グローウィン様AI推進/情報管理担当 | Google Workspace、HubSpot、ATS、会計、人事給与等の接続可否/権限確認 |

本プロジェクトでは、グローウィン様の内情を深く理解する役割が重要になる。議事録/業務ログから取れる情報はAIで分析する一方、文字情報に出にくい会議体の空気感、部門間の関係性、実際の意思決定の癖、非公式な情報流通は、グローウィン様側の社内メンバーと連携して補完する。

### 概算プラン

| プラン | 前提 | 概算費用 | 内容 |
|---|---|---:|---|
| 基本プラン | グローウィン様側から社内業務理解/調整を担う1名をアサイン | 月額80万円程度 | BAAOは設計、分析、資料化、AIツール組み込み方針を担当 |
| 体制追加プラン | グローウィン様側で専任者を出せない場合 | 月額150万円程度を追加 | BAAO側で業務理解/現地伴走を担うコンサル人材を追加 |

金額は提案段階の概算であり、正式な契約条件、支払条件、スコープ外、変更管理はSoWで確定する。

### 成果物

| 成果物 | 内容 |
|---|---|
| AI時代の情報ガバナンス診断メモ | 現状課題、詰まり、優先論点 |
| 情報カテゴリ/権限マトリクス | 情報種別、部門/役職、AI利用範囲 |
| AI利用レベル定義 | L0〜L4、権限付与/剥奪ルール |
| AI利用台帳テンプレート | 部門、用途、ツール、接続データ、責任者、リスク分類 |
| AIリスク/影響評価シート | 高影響領域、顧客/社員/契約/情報漏えいへの影響 |
| AIツール/ベンダーチェックリスト | 学習利用、保存、国外移転、監査ログ、SaaS権限、契約 |
| 人間レビュー/外部送信基準 | 顧客向け、社内向け、人事/財務/法務向け |
| インシデント対応フロー | 情報漏えい、誤送信、権限外参照、差別的出力、顧客クレーム |
| コミュニケーション/会議体設計案 | 情報の流し方、会議体、参加者、入力/出力、意思決定ルール |
| 会社運営への組み込み案 | AIが論点整理し、人間が判断し、実行/振り返りまで回る運営サイクル |
| 90日ロードマップ/外販メニュー仮説 | 次フェーズ候補とクライアント向け診断/設計メニュー |

## 6. Phase 1 / 外販化の仮説

初期3ヶ月プロジェクト後は、1つの対象領域で実運用する。

候補:

1. 経営管理/CRM/財務データのAI接続ルール
2. 採用・人事データのAI利用ルール
3. コンサル提案書/議事録/顧客情報のAI利用ルール
4. 会議体/コミュニケーション運用のAI支援ルール
5. 経営思想/組織ミッションをAIに持たせる「会社の脳」実証

外販メニューは、以下の3段階で考える。

| メニュー | 内容 |
|---|---|
| AI時代の情報ガバナンス診断 | 組織情報、権限、SaaS、AI利用状況を整理し、AI利用可能範囲を設計 |
| Corporate AI Control Design | 実際の業務AI化に進む前の統制設計。部門別AI利用、レビュー、外部送信、会議体、意思決定、運用体制を作る |
| AI Governance Update / Advisory | 月次/四半期でのルール更新、事例共有、複雑案件レビュー、営業同行 |

レベニューシェアを設定する場合は、単なる資料提供ではなく、AIツール/規制/事例の更新、提案資料・診断テンプレートの更新、必要に応じた営業同行、複雑案件レビューまで含める必要がある。
