## 2. 外部事例: 国内大企業のAI推進

### 見せたい方向性

外部企業は、個人のチャット利用から、業務プロセスや組織施策へ移っている。

### 事例1: 中部電力 - ITサービスデスク x Now Assist

公開情報で、ServiceNow Now AssistをITサービスデスクに組み込み、運用効率、コスト最適化、ユーザー体験改善を狙う取り組みが紹介されている。

参加者への刺しどころ:
- NECの問い合わせ業務・サービスデスクに近い
- 「AIチャットを使う」ではなく、サービスデスク業務にAIを組み込む事例
- 繰り返し問い合わせ、一次回答、ナレッジ参照、人の介在ラインが論点になる

数字:
- 当日投影では、公開資料で確認できる数字があれば差し替える
- 数字が未確認の場合は、定量値を断定せず「運用効率・コスト・UXを同時に狙う国内事例」として扱う

### 事例2: Hitachi Energy - ITSM x AI / Agent

ServiceNow公式の顧客事例で、IT Service ManagementにNow Assist Skill KitやAI Agent Studioを組み合わせ、ITSMタスクや複数ステップのワークフローにAIを入れる方向性が紹介されている。

参加者への刺しどころ:
- エネルギー/インフラ系企業で、NECの運用保守文脈に近い
- 人間の監督を残しながら、役割別ワークフローを自動化する方向
- 将来像は「AIが勝手に全部やる」ではなく、「AIがドラフト/チェック/連携し、人が監督する」

### 事例3: 国内の全社AI推進

KDDI、SoftBank、NTT DATA、日立などの全社AI推進は、規模の話として短く扱う。第1回では深入りしない。

参加者への刺しどころ:
- 推進者/アンバサダーを置くだけでは足りない
- 成果を出すには、テーマ、業務プロセス、指標、報告の型が必要
- NECの11名推進者も、上期テーマを業務に落とす役割を担う

### 「飴」のBefore / After

危機感だけでなく、翌週から楽になる実感を入れる。

例:
- 月次報告: 情報収集、要約、ドラフト作成で4時間 -> 30分を目指す
- 議事録: 文字起こし、決定事項、ToDo抽出で1時間 -> 10分確認へ
- 問い合わせ一次回答: 過去FAQ検索、回答案作成、エスカレーション判断をAI補助

ここで強調するのは「人を置き換える」ではなく「毎回探す、まとめる、整える作業を軽くする」こと。

### 事例のまとめ

### キーメッセージ

AI活用の差は、モデル性能の差ではなく、業務に組み込む設計力の差になっている。

## 3. ITSM / 運用保守に近いAI活用

### NEC側に寄せる領域

- 問い合わせ対応
- 申請書/手順書チェック
- 会議/チャットからのナレッジ収集
- インシデント対応、変更管理は発展領域として触れる

### 例1: 問い合わせ業務

現状:
- 問い合わせ分類が人に依存する
- 過去回答の検索に時間がかかる
- 一次回答の品質が担当者でぶれる

AI活用:
- 問い合わせ分類
- 担当振り分け
- 関連ナレッジ検索
- 一次回答案生成
- エスカレーション判断

成果指標:
- 一次回答時間
- 自己解決率
- エスカレーション率
- 回答品質のばらつき

投影イメージ:
- サンプル問い合わせ文
- 参照元付きの回答案
- 人間が承認/修正する欄
- 第2回で精度の上げ方を扱う、と予告する

### 例2: 申請書チェック

現状:
- 記入漏れ、形式不備、添付漏れ、規程違反を人が見る
- チェック観点が人によって違う

AI活用:
- チェックリスト化
- 記入漏れ検出
- 添付漏れ検出
- 規程との差分確認
- 差し戻しコメント案生成

成果指標:
- 差し戻し件数
- チェック工数
- 不備検出率
- レビュー品質

投影イメージ:
- 記入漏れ
- 添付漏れ
- 規程違反
- 差し戻しコメント案

### 例3: ナレッジ収集

現状:
- チャットや会議にノウハウが残るが、後から探せない
- ベテランの判断基準が暗黙知のまま残る

AI活用:
- 会議/チャット文字起こしからノウハウ抽出
- 意思決定、作業手順、注意点、例外処理を構造化
- FAQ/手順書/ナレッジDBに変換

成果指標:
- 検索時間
- 引き継ぎ工数
- 同じ質問の再発率
- 属人タスク数

### キーメッセージ

運用保守領域では、AIの価値は「回答すること」だけではない。分類、チェック、記録、検索、標準化まで含めて、業務の流れに入れることが重要。

## 4. AI活用パターンの整理

### 3テーマとの対応

| 上期テーマ | 主に使うパターン | 補足 |
|---|---|---|
| 問い合わせ対応 | RAG / ナレッジ検索 + 業務ワークフロー化 | 参照元付き回答案、人による承認、対応履歴への記録 |
| 申請書/手順書チェック | 業務ワークフロー化 + Copilot/NGS | チェック観点リスト、規程照合、差し戻し文案 |
| ナレッジ収集・属人化排除 | RAG / ナレッジ検索 + Agent | 会議/チャットからノウハウ抽出、手順・例外処理の構造化 |

### パターン1: Copilot / NGSでの個人作業補助

向いていること:
- 要約
- 翻訳
- 文書校正
- メール/報告書ドラフト

限界:
- 個人利用で止まりやすい
- 業務プロセス上の責任分担やデータ連携までは変わらない

### パターン2: RAG / ナレッジ検索

向いていること:
- 手順書、FAQ、過去対応履歴から回答する
- 最新版資料や類似事例を探す

注意点:
- 文書が古い、散らばっている、権限が曖昧だと精度が出ない
- 「検索できる」だけでは業務改善にならない。問い合わせや申請チェックなどの業務導線に接続する必要がある

### パターン3: Agent

向いていること:
- 複数ツールをまたぐ作業
- 問い合わせを受けて、検索し、判断し、チケット更新や回答案作成まで行う
- 定期実行やイベント起点の自動処理

注意点:
- いきなり自律実行にしない
- まずは「提案・ドラフト・チェック」から始め、人が承認する形にする
- MCPは外部ツール連携の標準的な仕組みとして1行だけ触れる。非開発者向けには詳細説明しない

### パターン4: 業務ワークフロー化

向いていること:
- 申請書チェック
- 問い合わせ分類
- 月次報告
- インシデント記録

注意点:
- AI単体ではなく、入力、判断基準、承認者、記録先を決める必要がある

### キーメッセージ

AIを使うかどうかではなく、どの業務ステップにAIを入れるかを決める。推進者の仕事は、業務を分解してAIの置き場所を決めること。

## 5. NEC環境での現実的な進め方

### 前提

- NGS / NGS API / RAG / Microsoft 365 Copilot / NotebookLM などが利用候補
- 最高機密・極秘情報は利用不可
- 許可された生成AI環境で現実的に進める

### 現実的な進め方

1. いきなり高度なAgent化を狙わない
2. 上期テーマを業務フローに分解する
3. AIを入れる箇所を1つに絞る
4. 入力データ、判断基準、成果物、承認者を決める
5. Before / After と効果指標を置く

### 例: 問い合わせ業務

- 入力: 問い合わせ文、過去FAQ、対応履歴
- AI処理: 分類、関連情報検索、回答案作成
- 人の判断: 回答承認、例外判断
- 記録先: FAQ、対応履歴、チケット
- 指標: 一次回答時間、自己解決率、エスカレーション率

この例を宿題テンプレートと同じ型で見せ、「次回までに各グループの上期テーマをこの型に分解する」と接続する。申請書チェックの詳細分解は第2回の冒頭素材として温存する。

### キーメッセージ

AI導入は「何ができるか」から考えると広がりすぎる。「どの業務の、どの判断/作業を軽くしたいか」から始める。

## 6. ミニワーク

0:44-0:51で、宿題シートをその場で書き始めてもらう。全てを完成させる必要はない。まず1つの上期テーマを選び、以下を埋める。

1. 自グループの上期テーマは、どの業務プロセスに属するか
2. その業務で、時間がかかっている作業は何か
3. その業務で、品質がぶれている判断は何か
4. その業務で、毎回探している情報は何か
5. AIが「ドラフト」「チェック」「検索」「分類」「記録」のどれを担うと効果がありそうか

時間があれば1〜2名に共有してもらい、講師側から「そのテーマなら、まずAIに任せる候補はここ」とコメントする。

## 宿題

次回までに、各グループで上期テーマを以下の形に分解してもらう。

提出運用:
- 提出期限: 第2回の2営業日前まで
- 提出先: NEC側窓口経由でBAAOへ共有
- 単位: 推進者個人ではなく、原則としてグループ/テーマ単位
- 第2回冒頭で、提出物のうち2〜3件を匿名または許可範囲で公開分解する

| 項目 | 記入例 |
|---|---|
| 対象業務 | 問い合わせ対応 / 申請書チェック / ナレッジ収集・引き継ぎ / インシデント対応 |
| 現状の困りごと | 回答作成に時間がかかる、チェック観点が人でぶれる、会議やチャットのノウハウが残らない |
| 入力データ | 問い合わせ文、FAQ、対応履歴、申請書、規程、会議文字起こし、チャットログ |
| AIに任せたい作業 | 分類、検索、回答案作成、不備チェック、手順・例外処理の抽出 |
| 人が判断すること | 最終回答、例外対応、承認 |
| 成果指標 | 対応時間、差し戻し率、検索時間、引き継ぎ工数、品質 |
| 次回聞きたいこと | 精度を上げる方法、データ整備、業務フロー設計 |

## 今日の締めメッセージ

AI推進は、便利なAIを知っている人を増やす活動ではありません。

業務を分解し、AIを入れる場所を決め、成果指標を置き、現場で使える形にする活動です。今日の第1回では、外部事例と活用パターンを通じてその見取り図を作りました。次回は、問い合わせ業務と申請書チェック業務を題材に、実際にどう分解し、どう精度を上げるかに入ります。
